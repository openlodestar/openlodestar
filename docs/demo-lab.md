# 小游戏版演示：换掉一个词，看证据认不认

`docs/demo.html` 教人看「一条记录是怎么被核出来的」；`docs/demo-lab.html` 反过来：让人自己动手改这句话，再看系统认不认。

页面上一句话被拆成三个槽位：

> [北京保利] 在 [2021年12月5日] 举办了一场名为「[禹贡Ⅰ—盛清御瓷新风尚]」的拍卖会。

点任意一个词，判定卡原地翻成选词卡、列出能换的词；点一个新词，句子换掉、选词卡收起，结论和引文立刻回到原来那块位置。结论分八档：**强坐标**、**弱坐标**、**只找到相容证据**、**没有矛盾，但这不能证明**、**冲突候选**、**没对上，证据写的是别的**、**无从判断**、**这批证据没覆盖**，外加每一维各自的状态、支撑或反驳它的引文、来源、URL 与抓取时间。

这是一局有分数、有目标、能存档的小游戏，不是一块可以随便点的演示面板：每种结论只在第一次被收进图鉴时给分，八种结论各收一次、满 31 分通关。整局游戏固定在一个视口里，换词、读判据、收录、看进度都不需要上下滚动；任务、分数表、复盘、证据与说明都收在顶部的四个按钮后面，点开是浮在游戏上方的抽屉。页面不联网、不需要服务端，双击本地文件也能玩（只是 `file://` 下可能存不了进度）。

## 游戏机制：先看原则，再定规则

规则不是凭手感编的，先做了一轮调研，再只挑能被这一页直接兑现的原则落地：

| 原则 | 调研里的说法 | 落到本页 |
| --- | --- | --- |
| 计分是引导，不只是奖励 | 计分系统的功能之一是告诉玩家"什么值得做"（Lee 等，《Design Aspects of Scoring Systems in Game》，2017） | 分数只按**结论**给，不按点击次数、不按速度；分数表放在顶部「分数」按钮里，随时点开就能看"下一步该找哪一档" |
| 学习必须发生在核心循环里 | 教育游戏要把"玩的动作"和"学的动作"合成一个循环，不能玩一套、学另一套（Czauderna & Guardiola，《The Gameplay Loop Methodology as a Tool for Educational Game Design》，2019） | 玩家唯一的动作就是"换词 → 读判据"；学的内容就是判定卡上的逐维判据，没有单独的知识页或教程 |
| 解释性反馈优于对错反馈 | 只告诉对错的反馈，迁移效果明显差于附带解释的反馈（Moreno，《Role of Guidance, Reflection, and Interactivity in an Agent-Based Multimedia Game》，2005） | 每组不只说"强 / 弱"，而是点名最差那一维、写出你写的值与证据里的值，并说明这一维为什么不能算对上 |
| 有引导的发现，好过纯自由探索 | 对新手而言，几乎无引导的发现式学习效率显著更低（Kirschner、Sweller & Clark，《Why Minimal Guidance During Instruction Does Not Work》，2006） | 100 组组合不让人瞎撞：三章任务 + 每组的「下一步」提示，把搜索空间压到一次只动一维 |
| 失败—重试—成功要闭环 | 失败后能立刻重试、成功时给出解释，才形成学习闭环（Tiangong Zhi 的严肃游戏设计，2025） | 收不进去不扣分，只说明是"重复了 / 这档收过了 / 已通关"，并列出还缺哪几档 |
| 重复收益要递减，抑制刷分 | 重复同一动作会触发收益递减，这是通行的反刷设计（Fortnite Creative 的 diminishing returns 说明） | 同一组重复收 0 分、换组合收同一结论也 0 分，总分上限锁死在 31，刷不出更多 |
| 目标要看得见 | 目标梯度效应：离目标越近，投入越强；可见进度条把"还差多少"变得具体 | 顶部常驻分数条与 `已收 n / 8`，每章标 `n/m`，通关时分数条变绿并给出复盘入口 |
| 一次只加一个新规则，失败代价低 | 难度曲线要逐个引入新元素，且让失败的惩罚足够轻（常见关卡设计原则） | 三章按"要观察的差别有多细"分档，任何一组第一次收录都有分，收错只是 0 分、不倒退 |

刻意没有采用的三条，也写在这里，免得后来者以为是漏了：

- **不做随机奖励 / 抽卡**。这一页教的是"判据可复算"，随机奖励会让"为什么这组得 3 分"变得不可解释。
- **不做排行榜与连击**。速度与排名会把注意力从"读判据"挪到"点得快"，与学习目标相反。
- **不做纯自由发现**。把 100 组全摊开、不给任务，最容易被记住的会是"哪些词能凑出高分"，而不是"相容为什么不是对上"。


## 为什么是这个形态

这一页只服务一件事：**换个词，马上知道这句话在这批证据里站不站得住**。围着这一件事，能砍的全省掉：

- **没有「识别」按钮**。改词本身就是提问，再点一次确认是多余的一步；单独的那个按钮只做一件事——把这一组收进图鉴、换成分数。
- **没有词库，也没有拖动**。词库与拖拽是同一件事的第二、第三条路径，只会多出「拖错槽」「拖到一半丢了」的失败态；键盘与点击已经够用。
- **选项上直接写判据**。每个可换词右边带一个小标，说的是**这一维**：完全对上 / 口径相容 / 边缘相容 / 冲突候选 / 没对上 / 无从判断。它来自同一份冻结矩阵，而且就是"换成这个词之后、判定卡上这一维会显示什么"——点之前就能预知成色；鼠标停上去还会补一句整句会判成什么，两者分开写，不让"这一维对上了"被误读成"整句成立"。
- **结论跟着操作走**。判定卡与选词卡共用句子上方那一块位置，两者是同一张卡的正面和背面：点词就翻到选词，选完就翻回判定。换词不会把页面撑高、也不会让别的区块挪位，读判据不用滚屏、不用另找一块区域；卡上还写着"这一组值多少分、为什么值这个分"。
- **没覆盖时给方向，不给答案**。撞进「没覆盖」时不提供"点一下就到有结论组合"的按钮（那等于抄答案），只点名"三词里只有几维沾边、下一步先动哪一维、这一维缺的是什么"。

一句话：一次改词 = 两次点击（先点词、再点新词），结论与"这组值多少分"零点击到达；要把它变成分数，再点一次「收进图鉴」。打开页面时就已经有一条强坐标摆在眼前，第一次收录是免费的。

## 分数规则

**分数只由结论决定，八档一一对应；同一档只算第一次。** 分值不是"好坏排名"，而是"这条判据有多强、能排除多少"：

| 结论 | 分 | 为什么是这个分 |
| --- | --- | --- |
| 强坐标 | 8 | 三个词逐字对上，独立来源也够——目前证据能给的最强结论 |
| 弱坐标 | 6 | 三个词都对上，但独立来源不够；比对上了，却撑不起强结论 |
| 只找到相容证据 | 5 | 至少一维只是说法不同，可能是同一场，但这不能算对上 |
| 没有矛盾，但这不能证明 | 4 | 至少一维只排除了矛盾，没有正面证据 |
| 冲突候选 | 3 | 点名了另一个值，信息最多；但冲突只作候选，不压成反对 |
| 没对上，证据写的是别的 | 2 | 证据明确写了另一个值：能排除，但没有冲突那么强的指向 |
| 无从判断 | 2 | 解析不出可比的说法：这条线索到此为止 |
| 这批证据没覆盖 | 1 | 连一条记录都挂不上：只能说明"没查到"，不能说明什么 |
| **通关线** | **31** | 八档各收一次的总和。分数条填满 = 八种结论都亲眼看过 |

**玩家怎么从界面看出分数的来历**，有四个地方同时回答，不需要背：

1. **判定卡底部的计分口**：写着「这一组值 +N：它是「X」，这一档还没收过」。值 0 时写清是哪一种 0——同一组重复了、这一档已经收过了、还是已经通关。
2. **顶部「分数」按钮打开的分数表**：把上表原样列出来，含通关线怎么算。
3. **收录后的提示行**：`+6：弱坐标 已收进图鉴。`
4. **复盘表**：每一组都重新列出结论、得分与三维状态，分是怎么来的可以逐行核对。

分值也不含任何隐藏倍率、连击或时间奖励——同样的结论永远是同一个分，玩家可以在提交前自己算出来。

## 通关条件与难度分档

**通关 = 分数达到 31**，等价于八种结论各收一次。因为每档只算一次，所以通关路径至少是 8 次收录；又因为「强坐标」「弱坐标」「边缘相容」在 100 组里分别只有 1 / 1 / 2 组，光靠乱点凑不齐，必须读判据去找。

三章任务把八档排成一条由易到难的线，开局只要求最容易观察的两档：

| 章 | 要找的结论 | 为什么这个顺序 |
| --- | --- | --- |
| 第一章 · 先把对上和没对上分清 | 强坐标、没对上 | 打开页面就是强坐标；把专场名换掉，证据会明确写出另一个值。差别最大、最好观察 |
| 第二章 · 看起来像对上，其实不是 | 只找到相容证据、没有矛盾但这不能证明 | 开始要求分辨"说法不同"与"没被排除"，这是本页最想教的区别 |
| 第三章 · 证据的边界与反直觉的一档 | 冲突候选、无从判断、没覆盖、弱坐标 | 冲突不是反对、含糊说法判不了、只有一维沾边叫没覆盖，最后是"全对上也可能只到弱" |

章节只做**指引**，不做锁：提前在第三章的组合上拿到分照样算，任务清单会直接打勾并跳到下一张没打完的卡。当前章会高亮，并给出这一章"要找的差别是什么"的一句话提示。

## 防刷分：不靠扣分，靠上限

这一局不设"点错扣分"，失败只值 0 分，但重复劳动也换不出任何分数：

- **同一组重复收录 = 0 分**。按钮直接变成「这组已收 · 0 分」并禁用，提示"换掉一个词，去看另一组"。
- **换个组合收同一个结论 = 0 分**。按钮变成「这一档已收 · 0 分」，并列出还缺哪几档。这是"刷分"的主路径，堵在这里。
- **通关后锁分**。八档收齐后按钮变成「已通关 · 不再计分」，分数不会超过 31。
- **上限可算**。八档分值是固定表，没有任何隐藏倍率或时间奖励，所以"点一百次刷满"在数学上不成立。

## 进度怎么存

`localStorage` 的 `lodestar.demo-lab.progress.v1` 里**只存组合号**（`{version:1, submissions:[{comboId, at}]}`），不存分数、不存结论、不存判据。每次打开页面都用当前冻结矩阵重算：

- 矩阵换了、组合号不存在了，那条记录自动丢掉，不会带着旧分跑；
- 同一结论出现两次，只留第一次；
- 存档损坏或版本不对，退回空进度，页面照常能玩；
- `file://` 或隐私模式下 `localStorage` 可能直接抛异常，读写都包在 `try/catch` 里，失败就退回"这一局照玩、刷新不记得"。

「清空存档」需要点两次确认，清空后分数、任务勾选与复盘一起归零。

## 通关后的复盘

复盘收在顶部「复盘」按钮里，收录过至少一组后那里会标出组数（通关时自动打开一次）。每一行是一组收过的组合：序号、结论徽章、得分、完整句子、三维判据状态、以及当初为什么是这个结论。点任意一行，抽屉关掉、页面回到那一组，判定卡重新显示它的逐维判据与引文——包括当时把它判成"边缘相容"而不是"口径相容"的那一维。


## 槽位与可选词

三个槽位，**每个都至少两个候选**——这是硬要求：不允许出现「这个词只能配那个词」的死路。

| 槽位 | 候选数 | 可选词 |
| --- | --- | --- |
| 拍卖机构 | 4 | 北京保利；中国嘉德国际拍卖有限公司；保利香港拍賣；保利拍卖（演示用词） |
| 举办时间 | 5 | 2021年12月5日；2021年11月15日；2021年秋季；2021年8月（演示用词）；去年秋天（演示用词） |
| 专场名 | 5 | 禹贡Ⅰ—盛清御瓷新风尚；禹贡Ⅱ—郎世宁绘《纯惠皇贵妃油画像》暨重要宫廷艺术；禹贡Ⅲ—盛清御瓷新风尚；宸赏—明清御瓷珍玩；中國古董珍玩專場 |

候选数相乘是 4 × 5 × 5 = 100 组，正好等于组合上限（`MAX_COMBOS = 100`）。任意机构、任意时间、任意专场名都能互相拼——不再有"必须同时换两处才走得通"的路径。

**标了「演示用词」的三个值不是采集来的**：`保利拍卖`、`2021年8月`、`去年秋天` 在冻结底稿里都没有这种写法，是为了让「口径相容」（同一家，只是少写了城市）、「无从判断」（"去年秋天"解析不出可比的时间）这两条路真实可达才加的。它们的数据里带 `demoOnly: true`，页面上每个出现位置都有「演示用词」标记，候选列表下方还有图例，不会与采集值混在一起。其余 11 个候选都是冻结记录里逐字出现过的写法。

专场名不再拆成「主名 + 副题」两个槽。拆开时会出现死路（禹贡Ⅱ 只能配郎世宁，郎世宁 也只能配禹贡Ⅱ，想换一个就得先换另一个）；现在它就是一个槽、五个完整候选，换来换去都合法。


## 组合是怎么算出来的

`pnpm run demo:game`（`src/demo-page/build-demo-game.ts`）在构建时做五件事：

1. **给每条冻结记录定「证据到底写的是什么」**：同一字段先看「支持」行（模型说这页在支持这条断言），再看「反对」行，最后才用「不涉及」的行；同一类里取判据状态最强的原文值。全都取不到原文值，才退回断言自己的写法——退回断言是最后一步，否则「证据从没写过这个专场名」会被当成写过了。
2. **逐维比对**：玩家写的词与那条记录的原文值分别过一遍维度函数（机构、时间、文本三份实现，与门禁读的是同一套）。状态只有六种：完全对上 / 口径相容 / 边缘相容 / 冲突候选 / 没对上 / 无从判断。
3. **挑一条最贴合的记录**：六种状态折算成分（3 / 2 / 1 / 0 / −1 / −2）相加，分最高的那条就是这句话的对照记录。
4. **判覆盖**：至少两个词达到「口径相容」及以上，才算这批证据覆盖了这句话；不够就是「这批证据没覆盖」。
5. **定结论**：取三个词里**最差**的那一维，优先级从坏到好是 冲突候选 → 没对上 → 无从判断 → 边缘相容 → 口径相容 → 完全对上。三词全部完全对上时，才按那条记录自己的门禁给「强坐标」或「弱坐标」。

所以组合级结论永远比单维更保守：只要有一维只到口径相容，整句就不会写成"对上"；有一维冲突，整句就是「冲突候选」，不会被别的维盖过去。

输出写到 `docs/assets/demo-game-data.js`，内容是 `window.LODESTAR_DEMO_GAME = { ... }`。页面只查表，不重算。构建时还会核对八种结论各有至少 1 组，缺了直接失败，不擅自放宽候选去凑数；同时把每条组合指向的记录号、档位、门禁、标题与 `demo-data.js` 逐项对一遍，不一致就报错并提示先重跑 `pnpm run demo:data`。

## 覆盖与没覆盖

100 组组合里 68 组覆盖、32 组没覆盖，八种结论各有至少一组：

| 结论 | 组数 | 代表组合 |
| --- | --- | --- |
| 强坐标 | 1 | 北京保利 · 2021年12月5日 · 禹贡Ⅰ—盛清御瓷新风尚 |
| 弱坐标 | 1 | 北京保利 · 2021年秋季 · 禹贡Ⅱ—郎世宁… |
| 只找到相容证据 | 8 | 北京保利 · 2021年11月15日 · 禹贡Ⅱ—郎世宁… |
| 没有矛盾，但这不能证明 | 2 | 北京保利 · 2021年12月5日 · 禹贡Ⅱ—郎世宁… |
| 冲突候选 | 11 | 北京保利 · 2021年11月15日 · 禹贡Ⅰ—盛清御瓷新风尚 |
| 没对上，证据写的是别的 | 38 | 北京保利 · 2021年12月5日 · 禹贡Ⅲ—盛清御瓷新风尚 |
| 无从判断 | 7 | 北京保利 · 去年秋天 · 禹贡Ⅰ—盛清御瓷新风尚 |
| 这批证据没覆盖 | 32 | 北京保利 · 去年秋天 · 禹贡Ⅲ—盛清御瓷新风尚 |

**「只找到相容证据」怎么走到**：打开页面就是强坐标那一组，点「举办时间」换成 `2021年11月15日`，两下就到。卡片会写清楚「举办时间」这一维：你写的是「2021年11月15日」，证据里写的是「2021年秋季」，只是说法不同，算「口径相容」，不能算对上。整句结论就是「只找到相容证据」——有证据，但最多只到"说法不同"。

**「这批证据没覆盖」时也摆逐维**：判定卡会列出离它最近的那条冻结记录的逐维比对，并明说"这段不是结论：三个词里只有 1 维沾边，至少要两维达到「口径相容」及以上才算覆盖"。没覆盖既不是被反驳，也不是世界上不存在。卡片下面还会给一句"下一步先动哪一维"的方向，而不是一个能直接跳到答案的按钮。

「没对上，证据写的是别的」与「这批证据没覆盖」在页面上的差别必须一眼看得出来：前者能指名道姓说出证据写的是什么（比如你说 禹贡Ⅲ、证据写 禹贡Ⅰ），后者一条证据都指不出来。这条由 `src/demo-page/demo-lab.test.ts` 守着——它逐维复算每条组合的状态、核对覆盖判据、确认八种结论各至少一组、确认标了演示用词的值确实不在冻结证据里。

## 页面怎么用

整页从上到下只有四块，四块的位置永远不变：

1. **顶部 HUD**：`0 / 31` 分数、进度条、`已收 n / 8`、八格图鉴（已收的格子可以直接点回那一组）、一行"当前要找哪一档"，右边五个按钮——任务 / 分数 / 复盘 / 说明 / 音效。
2. **一句话**：三个带虚线下划线的词嵌在句子里，句子本身不换行到第二屏。
3. **判定卡**：点词时它会原地翻成选词卡，选完再翻回来。
4. **计分口**：一句"这一组值 +N、为什么值这个分" + 一个「收进图鉴 +N」按钮（不能收时写清是哪种 0 分并禁用）。

操作只有两条：

- **点句子里的词**：判定卡翻成选词卡，纵向列出该槽的全部候选（4 / 5 / 5 个）。每个候选是一个整行按钮：左边是词，右边是这一维的判据小标，长专场名可以折两行。选完卡自动收起、焦点还给句子，判定卡带着新的逐维判据翻回来。点卡外面、再点同一个词、或按 Esc 都会收起。
- **点「收进图鉴」**：能收就加分，同时顶部分数跳动、图鉴对应格亮起、复盘多一行；不能收就摇一下按钮并说清原因，不扣分。

四个按钮打开的是浮在游戏上方的抽屉，主界面不会被顶出去，抽屉自己内部滚动：

| 抽屉 | 里面有什么 |
| --- | --- |
| 任务 | 三章任务的完整清单与勾选状态，当前章高亮 |
| 分数 | 八档分值表 + 通关线怎么算 |
| 复盘 | 收过的每一组（结论、得分、完整句子、三维状态），点一行回到那一组 |
| 说明 | 六种维度状态的图例、「演示用词」是什么、四段边界说明、这批冻结数据的覆盖读数 |

判定卡里另有一个「这一组的证据」入口，打开的是同一套抽屉：这一组对照的那条记录、它的门禁档位、引文、来源、发布方档位、来源家族、抓取时间与 URL。深看的入口只在需要时展开，不占主界面。

## 一屏布局：怎么把一局装进一个视口

以前这一页是一个长网页：任务卡、分数表、复盘、说明依次排在判定卡下面，手机上要翻好几屏。现在改成"游戏壳 + 抽屉"，具体是三层：

1. **页面本身不滚**。`body` 定高一屏（`100dvh`）、`overflow:hidden`、纵向 flex；中间的游戏区 `flex:1;min-height:0`，HUD 与计分口按内容高度占位，剩下的高度全给判定卡。
2. **判定卡与选词卡是同一块区域的正反面**。外层 `.panel-wrap` 是 `position:relative;flex:1;min-height:0`，判定卡与选词卡都是 `position:absolute;inset:0;overflow:auto`。所以换词、开卡、关卡都不会改变任何一块的高度——这是"翻卡"而不是"撑页"。内容再多也只在卡内滚动，不会把页面顶出去。
3. **长内容进抽屉**。任务、分数表、复盘、说明、证据都放在 `#sheet` 里，`position:fixed` 覆盖在游戏上方，自己有 `max-height` 与内部滚动。抽屉打开时主界面尺寸不变。

小屏上另做三处收缩，只动排版不动内容：图鉴从 8 列改成 4 列 2 行、当前章那一行在手机上隐藏（内容在「任务」抽屉里）、判定卡的逐维表在手机上单行省略（完整值在「这一组的证据」里）。

## 动效、音效与手感

动效全部是 CSS keyframes 加少量 DOM 节点，没有 canvas、没有逐帧脚本、没有在主线程做重计算；每段动画都在 `animationend` 里把节点删掉，不攒 DOM。

| 什么时候 | 效果 | 怎么实现 | 能关吗 |
| --- | --- | --- | --- |
| 换词后判定卡刷新 | 卡片边框闪一圈金光 | `card-flash` | 跟随系统"减少动效" |
| 换词后 | 被改的那一维整行闪一下底色 | `row-ping` | 跟随系统"减少动效" |
| 收录成功 | `+8` 从按钮上飘起淡出 | `float-up`，JS 生成一个 `.fx-points` 节点 | 跟随系统"减少动效" |
| 收录成功 | 分数数字弹一下（1.28 倍回弹） | inline `transform` + `transition` | 跟随系统"减少动效" |
| 收录成功 | 图鉴对应格弹一下并亮起 | `dex-pop` | 跟随系统"减少动效" |
| 能收录时 | 计分口按钮缓慢呼吸（提示"这一组可以收"） | `claim-pulse`（2.6s 循环） | 跟随系统"减少动效" |
| 收不进去 | 计分口按钮左右摇一下 | `shake` | 跟随系统"减少动效" |
| 打开选词卡 / 抽屉 | 卡片从下方 6px 淡入 | `card-in`、`sheet-in`、`fade-in` | 跟随系统"减少动效" |
| 八档收齐 | 18 片礼花落下 + 一条「通关 · 31 / 31」横幅 | `confetti-fall`、`banner-in`，JS 生成节点后自删 | 跟随系统"减少动效" |

**减少动效**：`@media (prefers-reduced-motion: reduce)` 把全部动画时长压到 0.001ms，并且用 `display:none` 整层隐藏飘分与礼花；JS 里另有一道 `reducedMotion()` 判断，在生成节点之前就返回，不是"生成完再隐藏"。系统开了这个偏好，游戏照常可玩，只是没有位移与闪烁。

**音效默认关闭**。顶部按钮区里有一个「音效·关」按钮，点开才变成「音效·开」，此时换词、开卡、收录、收不进去各有一次很短的提示音（WebAudio 生成的正弦/三角波，几十毫秒）。没有任何背景音乐，也不会在没有用户操作时发声——第一次发声一定发生在用户点击之后。

**键盘全流程可用**：Tab 依次走过顶栏链接 → 五个 HUD 按钮 → 当前章 → 三个词 → 计分口；焦点样式是奶油色描边，始终可见。在词上按 Enter 或空格打开选词卡，方向键上下（或左右）在候选里移动，回车选中；Esc 收起并把焦点还给这个词。更快的做法是**在词上直接按左右方向键换词**，不用开卡。抽屉打开时 Tab 被限制在抽屉内部循环，Esc 关闭并把焦点还给打开它的按钮。整个通关过程可以完全不碰鼠标。

## 实测读数

以下是在本地起 `pnpm run demo:serve --port 3019`、用 Chromium 真点页面读出来的，不是按规则推的：

**一屏之内（四种视口，每一行都读了页面总滚动高度与视口高度）**：

| 视口 | 初始 | 选词卡展开 | 说明抽屉 | 复盘抽屉 | 判定卡内部 |
| --- | --- | --- | --- | --- | --- |
| 1280×800 | 800 / 800 | 800 / 800 | 800 / 800 | 800 / 800 | 497 / 497 |
| 1440×900 | 900 / 900 | 900 / 900 | 900 / 900 | 900 / 900 | 597 / 597 |
| 375×667 | 667 / 667 | 667 / 667 | 667 / 667 | 667 / 667 | 331 / 331 |
| 390×844 | 844 / 844 | 844 / 844 | 844 / 844 | 844 / 844 | 507 / 507 |

"800 / 800"是 `document.documentElement.scrollHeight / window.innerHeight`，"497 / 497"是判定卡的 `scrollHeight / clientHeight`。四种状态下页面纵向偏移始终为 0、横向 `scrollWidth` 等于 `innerWidth`（1280 / 1280、1440 / 1440、375 / 375、390 / 390），HUD、句子、判定卡、计分口四块矩形互不重叠，也没有 `pageerror` 或 console 报错。375×667 另外把 100 组组合全部走了一遍：判定卡溢出量为 0，计分口底边最高 659px，仍在 667 以内。

- **一次完整通关**：**15 次操作 = 7 次换词 + 8 次收录**，分数从 `0 / 31` 走到 `31 / 31`，分数条 100% 并变绿、八格图鉴全亮、按钮变成「已通关 · 不再计分」、复盘 8 行。选路方式是"每一档挑一组离当前值最近的组合"，也就是一个会读小标、只动一列的玩家。上一版文档记的是 17 次（9 换 + 8 收），差别来自测量脚本选的那几组不同，机制、分值与组合矩阵都没动。
- **六种维度状态各一次**：通关那一局的复盘里逐组统计到 `exact`（强坐标、弱坐标）、`caliber`（口径相容）、`edge`（边缘相容）、`conflict`（冲突候选）、`mismatch`（没对上）、`unknown`（无从判断）六种都在，没有哪一态只存在于理论里。
- **全键盘通关**：只用 Tab / Shift+Tab / 方向键 / 回车 / Esc，不碰鼠标，同样走到 `31 / 31`、`已收 8 / 8`、分数条 100%、图鉴 8 格点亮、复盘 8 行、存档 333 字节。
- **防刷分（页面实测）**：清空存档后收录初始那组 → `8 / 31`，按钮立刻变成「这组已收 · 0 分」并禁用；换到另一组同判「没对上」的组合，按钮是「这一档已收 · 0 分」，分数仍是 `8 / 31`，没有再涨。
- **防刷分（规则层实测）**：同一组连提交 20 次，返回 20 次 `repeated-combo`，总分与第一次相同。这是单测里跑的，不依赖浏览器。
- **存档**：刷新页面后分数仍是 `31 / 31`、`已收 8 / 8`、复盘 8 行，通关文案还在；脏存档（未知组合号、重复组合、重复结论）读回后只剩 8 条合法记录，分数仍是 31。


## 站点地图

`docs/` 下三页构成一个站，不是三个孤岛页面。三页共用同一条顶栏（样式只有一份，在 `docs/assets/site-nav.css`），链接全部是相对路径，所以 `pnpm run demo:serve`（`http://`）、GitHub Pages（`docs/` 目录发布）与双击 `file://` 打开三种方式都成立。

| 页面 | 回答的问题 | 给谁看 |
| --- | --- | --- |
| `index.html` | 这东西是做什么的、现在到哪一步 | 第一次来的人 |
| `demo.html` | 一条结论凭什么算数：拆成哪些字段、每个字段的引文与出处、判成强还是弱、最后给不给坐标 | 想核对一条记录的人 |
| `demo-lab.html` | 换掉一个词，证据还认不认；八种结论各收一次，看自己能不能分清"相容"和"对上" | 想自己动手试的人 |

怎么跳：

- 首页首屏有「先看两个演示」按钮，正文第一段就是两个演示各一句说明——各自回答什么问题、差别在哪，点之前就能选。
- 三页顶栏都是同一组链接：主页 / 逐条演示 / 小游戏 / GitHub。任何一页都能直接跳到另外两页，也能回首页，没有死路。
- 顶栏在窄屏（320 宽）会把链接折到第二行，不会横向溢出；全部是原生链接，Tab 可逐个聚焦，焦点是奶油色描边。

`node scripts/check-site.mjs` 把这条关系当硬性检查：三页都必须引用 `assets/site-nav.css`、必须带同一组导航链接、站内链接必须是相对路径且指向真实存在的文件。

## 本地预览（只绑本机）

页面本身双击就能打开，不需要服务端。要在浏览器里用 `http://` 地址看（比如想在手机上调试，或确认相对路径都对），起一个只读 `docs/` 的静态服务：

```bash
pnpm run demo:serve                    # 默认 http://127.0.0.1:3013/demo-lab.html
pnpm run demo:serve --port 3014        # 3013 被占用时换端口
```

- **入口**：`http://127.0.0.1:3013/demo-lab.html`（小游戏页）、`http://127.0.0.1:3013/demo.html`（逐条记录演示）。
- **停止**：在那个终端按 `Ctrl+C`。终端关掉或机器重启，服务也跟着消失——这是预期行为，不是页面坏了。
- **端口被占**：脚本会直接报错并点名是哪个端口，按提示加 `--port` 换一个；也可以用 `netstat -ano | findstr :3013` 找出占用者。
- **边界**：只绑 `127.0.0.1`（局域网与公网都访问不到），只读 `docs/`，不联网、不读 `.env`、不计费，只做本地静态预览，不是部署。

## 边界

- 页面只做查表与展示，不检索、不抓页、不调模型。所有结论都是构建时用真引擎算好并冻结的。
- **分数是学习工具，不是证据评级**。它只奖励"这一档判据第一次被看到"，不衡量这批证据本身够不够硬；31 分只说明八种结论你都亲眼看过了，不说明任何一件器物的来源被确认。
- 存档只写在玩家自己的浏览器里（`localStorage`，只存组合号），不上传、不跨设备、不参与任何统计。
- 可选词只来自这 9 组冻结记录（`poly-2021-autumn` 加五个 `examples/demo-batch-*`），外加三个明确标注的演示用词，不是整个市场的代表。
- 「这批证据没覆盖」说的是这批冻结快照没覆盖到，不是「世界上不存在」。
- 组合级结论里没有「被反驳」：这一层只到「冲突候选」与「没对上」，因为判据只回答"原文写的是不是这个值"，不替你判定对方在反驳你。记录级档位（强 / 弱 / 被反驳 / 查不到）在逐条演示页 `docs/demo.html` 里看，小游戏的判定卡只把"对照记录自己的档位"作为旁注写出来。
- 演示用词是演示的一部分，不是采集结果：它们在冻结底稿里找不到出处，页面上有「演示用词」标记与图例；如果把这一页当证据清单引用，应当只看没带标记的候选。

## 已知隐患

- **日期解析器不校验非法日期**。`parseTimeScope` / `parseSingleDate` 只按数字位匹配，`2021年2月30日` 会原样给出 `2021-02-30` 这种不存在的日期，不会回退到 3 月 2 日，也不会报错。当前冻结数据里没有这类写法，所以不影响任何演示读数；本轮只记录、不改。将来接真实抓取时，需要在入口按日历校验，或把解析失败的日期直接当作 `null`。

## 本地实时实验服务（不部署）

如果想知道「输入任意组合，今天真去查会怎样」，有 `scripts/demo-live-server.mjs`（`pnpm run demo:lab-server`）。

**这个服务不部署、不进 Pages、只作本机实验。** 它只在 `127.0.0.1:3014` 上监听，密钥从仓库根的 `.env` 读、只在服务端使用，既不进前端也不进仓库。

它默认**拒绝运行**：不加 `--allow-spend` 就直接打印一段说明并退出，不装载引擎、不读密钥、不发任何请求。理由是每次调用都会真的搜索、抓页、调模型，花的是真钱。

要跑，得显式同意：

```bash
pnpm run demo:lab-server -- --allow-spend
```

然后在另一个终端调它：

```bash
curl -X POST http://127.0.0.1:3014/verify \
  -H "Content-Type: application/json" \
  -d '{"sentence":"北京保利在2021年12月5日举办了「禹贡Ⅰ—盛清御瓷新风尚」专场","confirm":true}'
```

服务在处理前会先打印这次调用的预估量（搜索次数、抓页数、大约多少次模型比对，按 `LODESTAR_MAX_SEARCH_CALLS` 与 `LODESTAR_MAX_PAGES` 算）。请求体里 `confirm` 不是 `true` 就返回 428 并附上这份预估，不花钱。产物落在 `.openlodestar-demo/live-server/<时间戳>/`，不进 `examples/`，也不会被 `pnpm run demo` 清掉。

它返回的是一场的运行摘要（每条记录的门禁与理由、坐标、被护栏暂停的断言号、是否被护栏收手），不是可复现的演示。在线结论本来就不可复现——搜索排名与页面可达性随时会变，这里的结果只用于实验与诊断。
