# 小游戏版演示：换掉一个词，看证据认不认

`docs/demo.html` 教人看「一条记录是怎么被核出来的」；`docs/demo-lab.html` 反过来：让人自己动手改这句话，再看系统认不认。

页面上一句话被拆成四个槽位：

> [北京保利] 在 [2021年12月5日] 举办了一场名为「[禹贡Ⅰ]—[盛清御瓷新风尚]」的拍卖会。

点任意一个词，旁边就列出能换的词；点一个新词，句子换掉，结论和引文立刻出现在句子下面。只有三选一的结论：**对**、**不对**、**这批证据没覆盖**，外加支撑或反驳它的引文、来源、URL 与抓取时间。页面不联网、不需要服务端，双击本地文件就能用。

## 为什么是这个形态

这一页只服务一件事：**换个词，马上知道这句话在这批证据里站不站得住**。围着这一件事，能砍的全省掉：

- **没有「识别」按钮**。改词本身就是提问，再点一次确认是多余的一步。
- **没有词库，也没有拖动**。词库与拖拽是同一件事的第二、第三条路径，只会多出「拖错槽」「拖到一半丢了」的失败态；键盘与点击已经够用。
- **选项上直接写结论**。每个可换词右边带一个小标（对 / 弱 / 不对 / 查过没找到 / 没覆盖），它来自同一份冻结矩阵——点之前就知道这一步会得到什么，不用靠试。
- **结论跟着操作走**。判定卡就在句子下面，改完立刻更新，不用滚屏、不用另找一块区域。
- **没覆盖时给去处**。一旦撞进「没覆盖」，卡片直接列出改一两个词就能落到有结论组合的按钮，点一下到目的地。

一句话：一次改词 = 两次点击（先点词、再点新词），结论零点击到达；打开页面时就已经有一条有结论的组合摆在眼前。

## 槽位与可选词

每个槽的可选词只从冻结底稿里真实出现过的值里取，没有一个是编的：

| 槽位 | 可选词 |
| --- | --- |
| 拍卖机构 | 北京保利；中国嘉德国际拍卖有限公司 |
| 举办时间 | 2021年12月5日；2021年11月15日；2021年秋季；2021年12月 |
| 专场主名 | 禹贡Ⅰ；禹贡Ⅱ；禹贡Ⅲ |
| 专场副题 | 盛清御瓷新风尚；郎世宁绘《纯惠皇贵妃油画像》暨重要宫廷艺术；明清御瓷珍玩 |

四槽相乘是 2 × 4 × 3 × 3 = **72 种组合**。组合上限设在 100：再多就得砍每槽的选项数，否则冻结数据会大到不像个演示。

专场名在底稿里是一个字段，写作「主名—副题」；页面把它拆成两个槽，是为了让人能单独换掉其中一半。组合判定时再把两半拼回原字段去比。

## 组合是怎么算出来的

`pnpm run demo:game`（`src/demo-page/build-demo-game.ts`）在构建时做三件事：

1. **生成 72 种组合**，每种组合就是一串四个具体的词。
2. **在冻结记录里找同款**：一条记录必须四个值全部相等才算命中。命中后按门禁档位优先挑一条——强优先于弱，弱优先于被反驳，同档再按批次顺序与记录号，保证每次构建挑到的是同一条。
3. **把引擎算出来的结论冻结进数据文件**：`gate`（门禁档位）、`bucket`（四分类）、逐字段的裁决与证据等级、共现页、坐标（等级、证据等级、URL、检索短语、是否过时）、证据条数。

输出写到 `docs/assets/demo-game-data.js`，内容是 `window.LODESTAR_DEMO_GAME = { ... }`。页面只查表，不重算。

构建前先跑 `pnpm run demo:data`，因为小游戏引用的记录摘要来自 `docs/assets/demo-data.js`；构建脚本会核对两边的记录号、四个字段值与门禁是否一致，不一致就报错并提示先重新生成演示数据。

## 覆盖与没覆盖

72 种组合里，只有 4 种能在冻结记录里找到同款：

| 组合 | 结论 |
| --- | --- |
| 北京保利 · 2021年12月5日 · 禹贡Ⅰ—盛清御瓷新风尚 | 对（强坐标） |
| 北京保利 · 2021年11月15日 · 禹贡Ⅰ—盛清御瓷新风尚 | 不对（两家独立来源当场反驳） |
| 北京保利 · 2021年秋季 · 禹贡Ⅱ—郎世宁绘《纯惠皇贵妃油画像》暨重要宫廷艺术 | 对，但只有单一独立来源 |
| 北京保利 · 2021年12月 · 禹贡Ⅲ—盛清御瓷新风尚 | 查过，这批证据里没有 |

其余 **68 种**是「这批证据没覆盖」。这不是系统的失败，是它的诚实边界：这些组合大多是把两三条记录的不同部分拼在一起拼出来的，现实里没有任何一条冻结记录同时写着这四个值。页面会列出这四个词各自在多少条记录里出现过，并明说「四个词都出现过，但没有任何一条记录同时写着这四个值」——**不搬运旧证据，也不判成被拒收**。

「不对」和「没覆盖」在页面上的差别必须一眼看得出来：前者挂着反驳该断言的引文，后者一条证据都不显示。这条规则由 `src/demo-page/demo-lab.test.ts` 逐组合守着——72 条组合每条的结论与冻结数据逐项比对，被反驳的组合必须有反驳引文，「没覆盖」的组合必须有空记录、空证据。

## 页面怎么用

- **点句子里的词**：任意一个带下划线的词都能点，点了就在那个词的上方弹出一小片浮层，列出该槽的可换词，每个词右边跟着它会把结论带到哪里。浮层不占句子下方的位置，判定卡在原地不动；靠近句子末尾的词也一样，上方放不下就翻到词的下方，再不够就夹进屏幕内，手机上不会横向溢出。
- **点一个新词**：句子换掉，下方判定卡立刻更新。浮层不收起，同一组里再换一个词只要再点一次；点浮层外或再点同一个词就收起。
- **键盘**：Tab 走到某个词，回车或空格打开；焦点落在当前这个词上，方向键左右切换，回车选中；Esc 收起并回到句子上。拖动已经去掉——它从来不是任何人的唯一路径，却会带来「拖错槽」「拖到一半丢了」这些失败态。
- **判定卡**：徽章写结论，下面一句为什么，再摆最多三条决定性证据（引文、来源、发布方档位、来源家族、抓取时间、URL）。被反驳时先摆反驳的那几条；换过哪个词就先摆那个字段的证据。
- **展开完整拆解**：判定卡下方的折叠区，列四个字段各自的全部证据、共现页与坐标。默认收起——决定性证据已经在上面了，想深看的人再展开。
- **没覆盖**：判定卡不显示任何证据，只说明这四个词各自在多少条记录里出现过、没有任何一条记录同时写着它们，并给出三条「改一两个词就能看到结论」的去处，点一下直接落过去。
- **回到原句**：改过词之后判定卡右上角出现这个小按钮，一键还原。

## 边界

- 页面只做查表与展示，不检索、不抓页、不调模型。所有结论都是构建时用真引擎算好并冻结的。
- 可选词只来自这 9 组冻结记录（`poly-2021-autumn` 加五个 `examples/demo-batch-*`），不是整个市场的代表。
- 「查过，这批证据里没有」说的是这批冻结快照没覆盖到，不是「世界上不存在」。
- 中国嘉德的 36 种组合全部没覆盖，因为嘉德记录的时间与专场名不在可供选择的词里。没有为了好看往里塞新词。

## 本地实时实验服务（不部署）

如果想知道「输入任意组合，今天真去查会怎样」，有 `scripts/demo-live-server.mjs`（`pnpm run demo:lab-server`）。

**这个服务不部署、不进 Pages、只作本机实验。** 它只在 `127.0.0.1:3014` 上监听，密钥从仓库根的 `.env` 读、只在服务端使用，既不进前端也不进仓库。

它默认**拒绝运行**：不加 `--allow-spend` 就直接打印一段说明并退出，不装载引擎、不读密钥、不发任何请求。理由是每次调用都会真的搜索、抓页、调模型，花的是真钱。

要跑，得显式同意：

```bash
pnpm run demo:lab-server -- --allow-spend
```

然后在另一个终端调它：

```bash
curl -X POST http://127.0.0.1:3014/verify \
  -H "Content-Type: application/json" \
  -d '{"sentence":"北京保利在2021年12月5日举办了「禹贡Ⅰ—盛清御瓷新风尚」专场","confirm":true}'
```

服务在处理前会先打印这次调用的预估量（搜索次数、抓页数、大约多少次模型比对，按 `LODESTAR_MAX_SEARCH_CALLS` 与 `LODESTAR_MAX_PAGES` 算）。请求体里 `confirm` 不是 `true` 就返回 428 并附上这份预估，不花钱。产物落在 `.openlodestar-demo/live-server/<时间戳>/`，不进 `examples/`，也不会被 `pnpm run demo` 清掉。

它返回的是一场的运行摘要（每条记录的门禁与理由、坐标、被护栏暂停的断言号、是否被护栏收手），不是可复现的演示。在线结论本来就不可复现——搜索排名与页面可达性随时会变，这里的结果只用于实验与诊断。
