# 证据分拣：上甩收下，下甩放走

一句话：**屏幕下方滑过一条说法，你只有三秒多；能直接当支撑的往上甩收下，旁证留到每件器物的最后三拍再收，其余往下甩放走。**

`docs/demo-sort.html` 是另开的一页。`docs/demo-lab.html`（改词 + 八档图鉴 + 31 分线）原样保留，可以并排对比：那边是"自己拼一句话、看系统怎么判"，这边是"系统把一条条说法递到手上，你替它分拣"。两页读同一份冻结矩阵、调同一套维度函数，判定口径一个字没改。

## 一局的形状

- 两件器物，每件十条说法，共 20 拍；每拍一张证据卡，倒计时 3.2 秒（第二轮 2.8 秒）。
- 一屏之内玩完：上面是这一件的断言卡（机构 / 时间 / 专场三个值），下面是计时条、证据卡、判定行和两个动作按钮。
- 判定行就在证据卡正下方，**停留 1.2 秒再发下一张牌**，并且一直留到下一次判定才被替换——一行二十来个字读得完。
- 三颗心。心掉光提前结束，按已打的拍数结算。
- 一局 20 次判决 + 1 次开始。这一版的最优分是 **163**，S 线 150。

## 核心循环：一次挥动 = 一次判决

| 动作 | 触屏 / 鼠标 | 键盘 | 按钮 |
| --- | --- | --- | --- |
| 收下 | 把证据卡往上甩过 34px | `↑` / `W` | 「收下」 |
| 放走 | 往下甩过 34px | `↓` / `S` | 「放走」 |
| 开始 / 重开 | 点「开始」 | `空格` / `回车` | 「开始」 |

甩不到 34px 不再静默失败：卡片弹回原位、抖一下，判定行立刻写「甩得不够（要 34px 以上）：再甩长一点」，计时照走。点一下卡片不当作判决，提示「点卡片不算数：上甩收下、下甩放走」。

证据卡上直接并排放着要比较的两行：`本件 2021年12月5日` 与 `这条 2021年秋季`。长专场名会换行显示完整，不再用省略号截断。

## 六种状态在玩法里各自是什么后果

判定不在页面里算。每条说法属于哪种状态，是构建时用引擎的维度纯函数算好、冻结进数据的。玩法只决定"这个状态 + 这个动作 = 多少分、连击怎么走、掉不掉心"：

| 状态 | 收下 | 放走 | 超时 |
| --- | --- | --- | --- |
| 完全对上（按规则归一后一致） | **命中**：10 × 倍率，连击 +1 | 漏判：0 分，连击断 | 0 分，连击断 |
| 口径相容（说法不同、可能是同一场，但不能算对上） | +8，**连击断** | 0 分（不扣，也没拿） | 0 分，连击断 |
| 边缘相容（没有矛盾，但这不能证明） | +4，**连击断** | 0 分（不扣，也没拿） | 0 分，连击断 |
| 冲突候选（点名了另一个值，只作候选、不压成反对） | 0 分，**掉一颗心**，连击断 | +1 | 0 分，连击断 |
| 没对上（证据写的是别的值） | 0 分，**掉一颗心**，连击断 | +1 | 0 分，连击断 |
| 无从判断（解析不出可比的说法） | 0 分，连击断 | +1 | 0 分，连击断 |

这张表就是"相容证据不等于直接支持"的机制化：

- **口径相容收下有 8 分，但连击立刻归零。** 连击是倍率的唯一来源，归零意味着后面每一拍都少拿一档。所以收不收不在"这条说法像不像"，而在"后面还有没有命中"。
- **边缘相容同理，只是给得更少（+4）**：它在说"没有矛盾"并不等于"能证明"。
- **冲突候选与没对上收下直接掉心**，放走才对；错的是把它当支撑，不是这条说法本身的存在。
- **完全对上放走是漏判**：0 分且连击归零，比任何"放对"都疼。这把"该收的必须收"立住了。
- **无从判断**收下不伤，但断连击、白占一拍——它是"什么也没说"的代价。

## 连击、倍率与兑现窗口

倍率只看**连续命中**：连击 0 是 ×1，1 是 ×2，2 起是 ×3（封顶 ×3）。连击在每件器物开始时清零。

| 连击 | 0 | 1 | 2 及以上 |
| --- | --- | --- | --- |
| 倍率 | ×1 | ×2 | ×3 |

**每件器物的最后三拍不会再发命中。** 这是公开规则，环形进度也在标题行写着「收尾窗口：这三拍不会再发命中」。它制造了唯一的兑现窗口：这三拍里收旁证不会亏倍率，中段收则一定亏。

中段收一条口径相容的账是这么算的（以第一局的顺序为例）：第三拍收下它 +8，连击从 1 归零，后面两次命中就从 20 + 30 掉成 10 + 20——净亏 12 分。放到最后三拍收，后面已经没有命中，+8 是白赚。同一个「口径相容」，位置不同、答案相反。

分数完全可复算：命中就是 10 × 当时倍率；旁证的分值是固定表；没有随机奖励、没有时间奖励、没有隐藏倍率。一局结束时逐条列出每条说法、它的真实状态、你做了什么、得分或掉心，六种状态各出现几次也一并列出。

## 为什么「只认字面相同」不再是最优

上一版的问题很硬：收下相容只多 3 分却冻住连击，数学上永远不如放走。"两边字面一样就收下、其余全放走"因此能拿满 146/146，六种状态只剩两种在实际决策里起作用。

现在三种打法在同一副牌上算出来是这样（六种牌序的读数完全一致）：

| 打法 | 怎么打 | 得分 | 评级 |
| --- | --- | --- | --- |
| 只认字面 | 只有完全对上收下，其余一律放走 | **127 / 163（78%）** | A |
| 逢旁证就收 | 口径/边缘相容见到就收，不看位置 | **139 / 163（85%）** | A |
| 分段取舍 | 命中有就收；口径/边缘相容中段放走、最后三拍收下 | **163 / 163（100%）** | S |

这两种"错"的打法互相冲突：一个把所有旁证都扔掉，一个把所有旁证都收下。它们都够不到 S 线（150），因为：

- 只认字面的人丢掉了收尾窗口里的 36 分（第一局 +20、第二局 +16）。窗口里的旁证本来可以白拿。
- 逢旁证就收的人在每件器物中段各断一次连击，两次命中从 20 + 30 掉成 10 + 20；两轮下来只剩 139 分。
- 分段取舍要求玩家同时读出两件事：**这条是完全对上还是旁证**，以及**现在是不是最后三拍**。只靠字面比对做不出第一个判断，只靠位置做不出第二个。

构建脚本会逐牌序校验这条不等式：`字面 < S 线`、`逢旁证就收 < S 线`、`稳健打法 = 理论最高分`。任何一条不成立，`pnpm run demo:sort` 直接失败，不会生成一版"字面也能满分"的数据。

## 牌序：局间会变，教学约束不变

- 每种牌序的第一拍固定是完全对上——第一次上甩就命中，不用读说明。
- 中段六拍打乱，**第六拍固定是完全对上**：中段收旁证一定会在后面还留一次命中的时候断连击，不能靠"后面没牌了"赌。
- 最后三拍打乱，且一定不发命中。
- 共 6 种牌序。点「再来一局」会换到另一种牌序，并有一半概率把两件器物的顺序对调；同一局内不会连续抽到同一种。

20 拍里六种状态的分布固定：完全对上 6、口径相容 6、边缘相容 1、冲突候选 2、没对上 3、无从判断 2。缺一种构建就失败。

第二轮真正要玩家感到的东西藏在日期精度里：同一个写法「2021年秋季」，对 `2021年12月5日` 这条断言是**边缘相容**（+4），对 `2021年11月15日` 是**口径相容**（+8）。同一个词、不同的断言精度，判据就不同——判定不是看词，是看词和这句话的关系。

## 评级

| 评级 | 分数线（占本牌序最优分） | 说明 |
| --- | --- | --- |
| S | ≥ 92%（150 / 163） | 命中没漏，旁证也只在兑现窗口里收 |
| A | ≥ 72%（118） | 取舍大体正确，几处亏了倍率 |
| B | ≥ 50%（82） | 把旁证当成了命中，或把命中放走了 |
| C | 0 | 先把两个动作的手感练熟 |

分数线按**这一牌序的理论最高分**折算，不是另定一个绝对目标；结算页同时写出「这一牌序最优 163 分；只认字面相同最多 127 分，见旁证就收 139 分」，玩家能自己看出差在哪。

## 数据从哪来：构建时算好，页面只查表

`pnpm run demo:sort`（`src/demo-page/build-sort-data.ts`）做六件事：

1. 读 `docs/assets/demo-game-data.js`——那份矩阵已由 `build-demo-game.ts` 从冻结底稿 `examples/` 生成，页面链路上不碰原始 JSONL。
2. 两件器物固定为矩阵里真实覆盖的两组：`g-01`（北京保利 / 2021年12月5日 / 禹贡Ⅰ）与 `g-07`（北京保利 / 2021年11月15日 / 禹贡Ⅱ）。
3. 按预先排好的十拍状态序列，从候选池里找第一条能算出该状态的写法；找不到就直接报错，不擅自放宽候选去凑数。
4. 用 `compareInstitutionDimension` / `compareTimeDimension` / `compareTextDimension` 算出状态与说明，连同器物、状态序列、计分表一起写进 `docs/assets/demo-sort-data.js`（`window.LODESTAR_SORT`）。
5. 生成 6 种牌序，并用动态规划求出每种牌序的理论最高分；再用「只认字面」「逢旁证就收」「分段取舍」三种打法各算一遍，校验上面那条不等式。
6. 校验六种状态一局里都出现；缺一种直接失败。

页面脚本 `docs/assets/demo-sort.js` 只做三件事：按牌序发牌、按动作查结算表、把结果与逐条复盘摆出来。**它不重算判定，也不放宽判定**。

「演示用词」的判据只看冻结语料：把 `docs/assets/demo-data.js` 里出现过的字段值与证据摘到的原值收集起来，不在其中的写法才标「演示」。这一版标出来的是 `保利拍卖`（同一家，只是少写了城市）与 `去年秋天`（解析不出可比时间）——这两个值是为了让「口径相容」「无从判断」两条路真实可达才放进候选池的。

## 不读字也能玩

页面用四层同时承载同一个判断，任何一层单独都能玩：

1. **颜色**：命中绿、口径蓝、边缘青灰、冲突琥珀、没对上暗红、无从灰；判定行、飘分、粒子都跟着状态走。
2. **进退**：命中时证据卡向上飞出、卡片外缘亮一圈绿光（不盖字）、爆开粒子；掉心时整屏红晕、器物卡红框；连击断在连击条上闪一下。
3. **数字**：分数、倍率、连击数、剩余心、第几件第几拍、何时进入收尾窗口，随时可见。
4. **一行字**：`上一拍 · 状态名 · 后果 · 分数`，就在证据卡下面。

首屏只有一句「完全对上就收下，连击会翻倍；说法不同（口径/边缘相容）先放走，等每件器物最后三拍再收」与一个「开始」按钮；完整分值表收在「分值怎么算的」折叠里，点开才看。

## 输入、无障碍与降级

- 指针：证据卡上 `pointerdown` / `pointermove` / `pointerup` + `setPointerCapture`，判定 ±34px；`touch-action:none` 保证纵向甩不被浏览器抢走。触屏与鼠标走同一条路径。
- 键盘：`↑`/`W` 收下、`↓`/`S` 放走、`空格`/`回车` 开始或重开；不需要鼠标就能打完整局。
- 读屏：判定行 `aria-live="polite"`；证据卡 `aria-label` 写「本件时间是…，这条说法是…」；心的容器按剩余数更新 `aria-label`。
- 切页暂停：`visibilitychange` 时停表并保存剩余时间，回来续上，不会因为切标签页被判定超时。
- 减少动效：`prefers-reduced-motion: reduce` 下动画压到最短、特效层整层隐藏，判定停留压到 0.9 秒，结算逻辑不变（账先落、表演后放），仍能打完整局。

## 测试守着什么

`src/demo-page/demo-sort.test.ts`（29 条，离线、零模型调用）守七件事：

1. **不许放宽判定**：每条说法的 `state` 与 `note` 都用引擎自己的维度函数逐字复算，必须一致。
2. **器物不是编的**：两轮的器物卡必须按 `comboId` 挂到冻结矩阵里 `covered` 的组合，记录号与三个值逐项相等。
3. **六态都碰得到**：每种状态至少一条，不许有一种只写在说明里。
4. **演示用词不多标**：`demoOnly` 必须等于"冻结语料里没有这个写法"。
5. **结算可复算**：倍率分段与上限、各动作的分/连击/心、超时，全部与数据表逐项核对。
6. **字面打不到 S**：逐牌序用页面真正在用的结算函数重算「只认字面」「逢旁证就收」「分段取舍」，前两者必须低于 S 线，第三者必须等于动态规划求出的理论最高分；数据里的 `best / steady / literal / eager` 也必须与复算一致。
7. **牌序与文案纪律**：每种牌序是完整排列、互相不同、第一拍命中、收尾三拍不发命中；六种状态标题就是引擎那六个；口径相容必须写「不能算对上」；收下冲突/没对上的提示里不许出现「命中」；S 级文案不许写「每条都判对了」。

测试会把页面脚本装进一个最小的假 DOM 里跑起来，拿到的是页面**真正在用**的那份结算函数（`window.LODESTAR_SORT_RULES`），不是测试另写一套。

## 实测读数

- **一局**：按分段取舍实打一局，**20 次判决、24.9 秒、163/163、S**，复盘 20 条全部标「最优」。
- **只认字面实打一局**：同样 20 次判决，**127/163、A**，够不到 S。
- **判定停留**：决定后判定行一直可见，下一张牌在 **1209ms** 后才出现；判定行在证据卡正下方（320 宽下与卡底相距约 10px，不再悬在屏幕中部）。
- **短甩与点击**：30px 上甩立刻提示「甩得不够（要 34px 以上）：再甩长一点」，分数不变；点击卡片提示「点卡片不算数」，计时继续。
- **320×568 开始页**：规则表折叠时 `scrollHeight = clientHeight`；展开后 799 > 546 变为可滚动，滚到底能看见表格最后一行（`tableBottom` 与表底对齐）。
- **牌宽**：320 下 294px、768 下 480px、1440 下 560px；大屏上器物卡 600px，整块上下居中，两侧与上下留白对称。
- **降级**：`prefers-reduced-motion` 下打完整局仍按同一套结算。
- **站点**：`node scripts/check-site.mjs` 覆盖全部 4 个页面并通过；`npx tsc --noEmit` 与 `npx vitest run src/demo-page` 通过。

## 还不好的地方

- **中段与窗口的差别要靠算一遍才信**：老手一眼能看出"旁证留到最后"，但新手前两局大概率仍会像"只认字面"那样打，拿到 A 而不是 S。判定行会写「连击断」，但"+8 换掉后面 20 分"这笔账没有直接算给玩家看。
- **只有两件器物、6 种牌序**：牌面本身只有 20 条，玩到第四五局会开始认牌。要真正耐玩，得从矩阵里生成更多合格器物（当前候选池只够撑起这六态齐备的两轮），这一步还没做。
- **六态分布不均**：边缘相容整局只有 1 条（第二件器物根本没有边缘相容），冲突候选 2 条。教学上够用，但"边缘相容"这条判据玩家一局只碰得到一次。
- **只有纵向甩**：不像旧页那样支持横向拨卡；本页不需要换页浏览，所以没做。
- **窗口内收下冲突仍会掉心，但分差只有 1 分**：复盘会把这种拍标成「可再想想」，可与「最优」的差别很小，S 线也没有逼玩家区分它们。
- **评级只按理论最高分折算**：163 是"全按公开规则打"的分，不能说明难度曲线是否合理；A 与 B 之间的差距还没有用真人数据校准过。
