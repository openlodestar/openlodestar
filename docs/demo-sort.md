# 证据分拣：上甩收下，下甩放走

一句话：**屏幕下方滑过一条说法，你只有两三秒（收尾三拍与长文案另加时）；能直接当支撑的往上甩收下，旁证留到每件器物的最后三拍再收，其余往下甩放走。**

`docs/demo-sort.html` 是另开的一页。`docs/demo-lab.html`（改词 + 八档图鉴 + 31 分线）原样保留，可以并排对比：那边是"自己拼一句话、看系统怎么判"，这边是"系统把一条条说法递到手上，你替它分拣"。两页读同一份冻结矩阵、调同一套维度函数，判定口径一个字没改。

## 本地打开这个演示

两种方式，任选一种；都不需要装依赖。

1. **最省事：直接双击 `docs/demo-sort.html`**，用默认浏览器打开即可（地址栏会是 `file:///.../docs/demo-sort.html`）。这一页的脚本、样式、数据全部走相对路径，没有 `fetch` / `XMLHttpRequest`、没有 ES module，也不联网，所以 `file://` 下能完整玩。实测（Chromium，390×844）：样式生效、`window.LODESTAR_SORT` 读到 4 个牌局、开始后第一拍判对得 10 分，控制台 0 错误、动态请求 0 条。
2. **要 HTTP 预览**（例如浏览器扩展拦了 `file://`）：在仓库根目录跑

   ```powershell
   pnpm run demo:serve -- --port 3021
   ```

   然后打开 `http://127.0.0.1:3021/demo-sort.html`。不想用 pnpm 也可以直接 `node scripts/serve-demo.mjs --port 3021`。服务只读 `docs/`、只绑 `127.0.0.1`，不联网、不计费。

**关于之前那个 3021 端口**：检查时它还在，进程是 `node scripts/serve-demo.mjs --port 3021`（当时 PID 412，父进程是一个 `cmd.exe /C` 终端），`http://127.0.0.1:3021/demo-sort.html` 返回 200。停掉：在那个终端按 `Ctrl+C`，或执行 `Stop-Process -Id 412`（先确认 PID 没变）。再起来就是上面那条命令；端口只是启动参数，默认端口是 3013，换别的号同理。

## 一局的形状

- 两件器物，每件十条说法，共 20 拍；每拍一张证据卡，基础倒计时第一件 2.6 秒、第二件 2.3 秒。
- **节拍跟着难度走**：收尾三拍要判「相容还是冲突」，统一多给 0.8 秒（3.4 / 3.1 秒）；值折成两行以上或总字数超过 14 时，按排版行数（每多一行 +0.8 秒）与字数（每多一字 +80ms）取较大者加时，封顶 1.8 秒。所以最长的专场名在中段约 4.4 秒、在收尾窗口约 4.9 秒；中段短说法仍是最紧的 2.6 / 2.3 秒。
- 一屏之内玩完：上面是这一件的断言卡（机构 / 时间 / 专场三个值），下面是计时条、证据卡、判定行和两个动作按钮。
- 判定写在这张证据卡自己的区域里（卡底一条虚线上方），**停留 1.2 秒再发下一张牌**；判定行是**固定高度占位**（`height:3.4em`、窄屏 3.4em / 宽屏 3.6em），文字长短都不改卡片高，舞台不跟着上下跳。
- 卡底同时有一条进度线走完，说明下一拍马上到，不会出现「按了没反应」的空白。
- 每件器物有十拍进度点：当前拍亮起，最后三拍描金边——不用记「还剩几张」。
- 三颗心。心掉光提前结束，按已打的拍数结算。
- 一局 20 次判决 + 1 次开始。这一版每种牌序的理论最高分都是 **199**，S 线 **180**（最优分的 90%），且 S 要求整局没有误收冲突/没对上。
- 结算复盘默认**只展开要改的几条**（「可再想想」），判对的折叠起来；头一行先写「先看 N 条可再想想；其余 M 条判对了」，点「展开全部 20 条」才铺开。只认字面的一局默认只显示 5 行、482px，一屏读完，不再滚三屏。

## 核心循环：一次挥动 = 一次判决

| 动作 | 触屏 / 鼠标 | 键盘 | 按钮 |
| --- | --- | --- | --- |
| 收下 | 把证据卡往上甩过 34px | `↑` / `W` | 「收下」 |
| 放走 | 往下甩过 34px | `↓` / `S` | 「放走」 |
| 开始 / 重开 | 点「开始」 | `空格` / `回车` | 「开始」 |
| 暂停 / 继续 | 点进度行右侧「暂停」 | `P` / `Esc` | 「暂停」 |
| 重来（局中） | 暂停页点「重来一局」→「确定重来」 | 先 `P` 暂停，再按 `R`，`Tab` 到「确定重来」按 `回车` | 同左 |

甩不到 34px 不再静默失败：卡片弹回原位、抖一下，判定行立刻写「甩得不够（要 34px 以上）：再甩长一点」，计时照走。点一下卡片不当作判决，提示「点卡片不算数：上甩收下、下甩放走」。

证据卡上直接并排放着要比较的两行：`本件 2021年12月5日` 与 `这条 2021年秋季`。长专场名会换行显示完整，不再用省略号截断。

## 暂停与重来

### 入口与键位

- **暂停**：进度行右侧常驻一个「暂停」按钮；键盘 `P` 或 `Esc` 等价。局中任何时刻都能按，包括收尾三拍和判定停留的 1.2 秒里。
- **继续**：暂停页的「继续」按钮，或再按 `P` / `Esc`。继续不会立刻开始计时：先倒数 **3、2、1**（`prefers-reduced-motion` 下是 2、1），数完才撤遮罩、接着走剩下的时间。倒数期间再按 `P` / `Esc` 会退回暂停页，不会误开。
- **重来**：只在暂停页里提供——点「重来一局」弹出内联确认（默认焦点在「先不重来」上），再点「确定重来」。键盘先按 `P` 暂停、按 `R` 打开确认，`Tab` 到「确定重来」按 `回车`。`Esc` 在确认框上表示「收回确认、继续暂停」，不会顺手恢复游戏。
- 确认框出现前不执行任何重置；取消后仍停在暂停页，计时保持冻结。

### 暂停时具体盖住了什么

遮罩是 `position:fixed;inset:0`、`z-index:30` 的整屏不透明渐变（`#0C1A33 → #070E1C`），没有半透明色、没有 `backdrop-filter` 模糊。下面这些元素逐项都在遮罩之下：

1. 顶栏数值区：当前分数、倍率、连击条与连击数、三颗心；
2. 进度行：第几件、第几拍，以及「收尾窗口」加时提示；
3. 换件提示（「换下一件 · 连击清零」）；
4. 十拍进度点（当前拍到哪、还剩几拍、是否进入收尾窗口）；
5. 器物卡：机构 / 时间 / 专场三行值、已命中的「命中」标记、掉心红框；
6. 计时条与右侧剩余秒数；
7. 证据卡：槽位、`这条` 说法、待判断的值、「语料外写法」徽章、判定行、卡底「下一拍」进度线；
8. 飘分、粒子、闪红等特效层。

除了盖住画面，遮罩打开时还给游戏外壳与顶栏同时加 `inert`、`aria-hidden="true"`，并把它们设为 `visibility:hidden`（不再绘制，浏览器查找、选中也拿不到）：读屏不会把下面的分数、牌面念出来，键盘也 Tab 不进去。实测暂停时壳与顶栏的 `visibility` 是 `hidden`、遮罩本身仍是 `visible`，恢复后壳回到 `visible`；在证据卡中心点做 `elementFromPoint`，命中的是遮罩内的元素，不是卡片。

### 计时与判定停留真的冻结了吗

冻结的是「这一次还剩多少」，恢复时从同一个读数接着走，不是重发一整拍，也不补时间。实测（Chromium，1280×800，`file://` 直开）：

| 场景 | 暂停瞬间 | 暂停 650ms 后 | 倒数结束、恢复运行 | 恢复 400ms 后 |
| --- | --- | --- | --- | --- |
| 收尾窗口的一拍（这一拍基础 3.4 秒） | **3175ms** | **3175ms** | **3173ms**（差 2ms） | **2760ms** |

- 倒数期间读数一直是 3175ms，说明那 1.8 秒倒数没有偷走答题时间；恢复后 400ms 读到 2760ms，计时条继续按原速度衰减（这 413ms 的流逝里含轮询间隔）。
- **判定停留**同样冻结：在判定落账后的停留里暂停，读到剩余 **1124ms**；600ms 后仍是 **1124ms**，卡片没有自己翻到下一拍。恢复后走完这段余量，`chipIndex` 从 7 变成 8，只前进一步。
- 暂停时不会触发 `decide`：判定函数在 `phase !== 'playing'` 时直接返回，所以不存在「暂停期间自动判了」。
- 暂停打断拖拽时，卡片直接回到中线、不结算这一拍；恢复后可以重新甩。

### 暂停页的 tips（最终文案）

六条都只讲通用规则，不读当前牌面、不提示这一拍该怎么判、不暗示本局剩下什么牌。脚本没有写这块列表的入口，它不会随局变化：

1. **先看器物卡，再读这张牌。**「本件」是这件器物的实际字段，「这条」是待判断的说法。
2. **字面完全对上就收下。** 这是最硬的支撑，收下得分；漏掉会断连击。
3. **口径相容 / 边缘相容只是旁证。** 中段收会断连击；每件最后三拍收，分值翻倍。
4. **冲突候选 / 没对上要放走。** 它们指向别的值，收下倒扣分、掉一颗心。
5. **每件器物单独记连击。** 换件时连击清零；时间到等于没判，0 分且断连击。
6. **最后三拍与长文案会自动加时。** 这几拍要判断「相容还是冲突」，所以放得更宽。

### 重来的牌序行为

「确定重来」走的是与结算页「再来一局」完全相同的 `startGame()` → `pickRun()`：从四个内容不同的牌局里抽一个，排除最近两局；六种牌序里换一种，并有一半概率把两件器物的顺序对调。不会重放刚才那一局的牌序，也不会只把同一副牌洗一遍。

实测从 `run-1` 重来后抽到 `run-2`（牌序 `order-4` → `order-2`），分数从 13 回到 0、拍次回到第 1 拍，暂停遮罩关闭，`aria-hidden` 与 `inert` 都已撤掉。

两个特殊状态也直接验过：收尾窗口的一拍（拍次 7）暂停后直接重来 → 拍次回 0、分数 0、换了一局；判定停留里暂停（`pauseKind=wait`、冻结 1104ms）后直接重来 → 拍次回 0、分数 0。两条走的是同一个 `restartGame()`。

### 切页

`visibilitychange` 进入隐藏状态时直接进暂停页（而不是只停表）：答题计时与判定停留都冻结，避免在后台被计时判超时。回来时停在暂停页，必须手动「继续」并走完倒数；如果是在倒数期间切走，回来仍退回暂停页。合成一次 `hidden` 事件实测：`playing` → `paused`，冻结读数 2213ms，600ms 后仍是 2213ms；恢复可见后仍停在暂停页，焦点在「继续」。

## 六种状态在玩法里各自是什么后果

判定不在页面里算。每条说法属于哪种状态，是构建时用引擎的维度纯函数算好、冻结进数据的。玩法只决定"这个状态 + 这个动作 = 多少分、连击怎么走、掉不掉心"：

| 状态 | 收下 | 放走 | 超时 |
| --- | --- | --- | --- |
| 完全对上（按规则归一后一致） | **命中**：10 × 倍率，连击 +1 | 漏判：0 分，连击断 | 0 分，连击断 |
| 口径相容（说法不同、可能是同一场，但不能算对上） | +8，**连击断**；兑现窗口里收 +16 | 0 分（不扣，也没拿） | 0 分，连击断 |
| 边缘相容（没有矛盾，但这不能证明） | +4，**连击断**；兑现窗口里收 +8 | 0 分（不扣，也没拿） | 0 分，连击断 |
| 冲突候选（点名了另一个值，只作候选、不压成反对） | **−6 分**，**掉一颗心**，连击断 | +1 | 0 分，连击断 |
| 没对上（证据写的是别的值） | **−6 分**，**掉一颗心**，连击断 | +1 | 0 分，连击断 |
| 无从判断（解析不出可比的说法） | 0 分，连击断 | +1 | 0 分，连击断 |

这张表就是"相容证据不等于直接支持"的机制化：

- **口径相容收下有 8 分，但连击立刻归零。** 连击是倍率的唯一来源，归零意味着后面每一拍都少拿一档。所以收不收不在"这条说法像不像"，而在"后面还有没有命中"。
- **边缘相容同理，只是给得更少（+4）**：它在说"没有矛盾"并不等于"能证明"。
- **冲突候选与没对上收下直接掉心，还倒扣 6 分**，放走才对；错的是把它当支撑，不是这条说法本身的存在。倒扣是可见的：飘分写 `−6 · −1♥`，复盘这一行写 `−6 分 · −1♥`，评语把 `6 × 误收条数` 算给玩家看。
- **完全对上放走是漏判**：0 分且连击归零，比任何"放对"都疼。这把"该收的必须收"立住了。
- **无从判断**收下不伤，但断连击、白占一拍——它是"什么也没说"的代价。

## 连击、倍率与兑现窗口

倍率只看**连续命中**：连击 0 是 ×1，1 是 ×2，2 起是 ×3（封顶 ×3）。连击在每件器物开始时清零，换件时页面上有一条提示「换下一件 · 连击清零，倍率回到 ×1」。

| 连击 | 0 | 1 | 2 及以上 |
| --- | --- | --- | --- |
| 倍率 | ×1 | ×2 | ×3 |

**每件器物的最后三拍不会再发命中。** 这是公开规则，标题行会写「收尾窗口：这拍多给 0.8 秒」，十拍进度点里这三拍描金边。它制造了唯一的兑现窗口：这三拍里收旁证不会亏倍率、分值还翻倍，中段收则一定亏。

中段收一条口径相容的账是这么算的：收下 +8，连击从 1 归零，后面两次命中就从 20 + 30 掉成 10 + 20——净亏 12 分。放到最后三拍收，后面已经没有命中，+16 是白赚。同一个「口径相容」，位置不同、答案相反。

分数完全可复算：命中就是 10 × 当时倍率；旁证的分值是固定表；没有随机奖励、没有时间奖励、没有隐藏倍率。一局结束时逐条列出每条说法、它的真实状态、你做了什么、得分或掉心，六种状态各出现几次也一并列出。

## 为什么「只认字面相同」不再是最优

上一版的问题很硬：收下相容只多 3 分却冻住连击，数学上永远不如放走；后来虽然把旁证的分调高，但「只认字面」仍能拿到 127/163、评 A 档，离 S 只差一线。

现在三种打法在每一种牌序上算出来是这样（六种牌序读数完全一致）：

| 打法 | 怎么打 | 得分 | 评级 |
| --- | --- | --- | --- |
| 只认字面 | 只有完全对上收下，其余一律放走 | **127 / 199（64%）** | B |
| 逢旁证就收 | 口径/边缘相容见到就收，不看位置 | **175 / 199（88%）** | A |
| 分段取舍 | 命中有就收；口径/边缘相容中段放走、最后三拍收下 | **199 / 199（100%）** | S |

只认字面比最优少 72 分，正好是每件器物收尾三拍里那些旁证翻倍后的总和（四条口径相容各 +16、一条边缘相容 +8）。它现在掉到 B 档，不再是「差一点就 S」。

这两种"错"的打法互相冲突：一个把所有旁证都扔掉，一个把所有旁证都收下。逢旁证就收够不到 S，是因为它在每件器物中段各断一次连击，两次命中从 20 + 30 掉成 10 + 20，两轮下来剩 175 分。分段取舍要求玩家同时读出两件事：**这条是完全对上还是旁证**，以及**现在是不是最后三拍**。只靠字面比对做不出第一个判断，只靠位置做不出第二个。

### S 线怎么定的：既要够得着，也要真的拉开

第三轮盲测里，一位"读懂再收"的玩家打到 178/199、A；第四轮他连打四局都是 178、89.5%、S。问题不是他打得不好，而是 S 线太松：178 分与粗糙的「逢旁证就收」（175）只差 3 分，S 线离粗糙打法的理论分只差约 1 分。更麻烦的是他每局都误收一条冲突、掉一颗心，分数照样 178——最高档只代表「窗口收全了」，不代表「没犯错」。

这一版同时动三处，缺一不可：

1. **S 线抬到最优分的 90%**：199 × 0.9 = 179.1，向上取整 **180**。盲测的 178 按分数已经不够；粗糙打法的 175 更够不到。S 与粗糙打法的差距从 2 分拉到 5 分（按百分比是 90% 对 88%）。
2. **误收冲突/没对上倒扣 6 分**：原来只掉心、不断分，现在分数、心、连击三样都付代价。盲测那种「178 + 每局一条误收」在新表下是 **172**。
3. **S 档加一道干净闸**：就算分数摸到 180，只要整局收错过一条冲突/没对上，页面直接按「S 要求整局没有明显误收」挡回 A，并写出「分数到了 S 线（X / 180），但收错了 N 条……」。最高档重新表示「打得干净」，而不只是「窗口收全了」。

四种打法在每一种牌序上算出来是这样（六种牌序读数完全一致）：

| 打法 | 怎么打 | 得分 | 评级 |
| --- | --- | --- | --- |
| 理论最优（DP 穷举） | 动态规划允许预知后续牌，求上界 | **199** | — |
| 分段取舍（只看规则与位置） | 命中就收；旁证中段放走、最后三拍收下 | **199** | **S** |
| 同一条打法，窗口里漏收 1 条 | 整局只有一次手误 | **183**（20 种牌序）/ **191**（4 种牌序） | **S** |
| 同一条打法，窗口里漏收 2 条 | 两次手误 | **175**（20 种牌序）/ **167**（4 种牌序） | **A** |
| 同一条打法，误收 1 条冲突/没对上 | 分数 172，且被干净闸挡下 | **172** | **A** |
| 逢旁证就收 | 不看位置，见旁证就收 | **175** | **A** |
| 只认字面 | 只有完全对上收，其余放走 | **127** | **B** |

结论：一个不靠记忆、只靠读懂「这条是完全对上还是旁证」和「现在是不是最后三拍」的打法，**不用看结算提示就能打出 199、自然拿到 S**；手滑漏收一次（183）仍留在 S；漏收两次、误收一条冲突、或逢旁证就收（175 / 172 / 167）都明确进不去。

**关于 178**：上一版 88.5% 的线是 177，178 能过；这一版 90% 的线是 180，178 过不了。这是有意的——盲测那四局 178 每一局都带着一条误收，不是干净局。如果保留「178 也能过」，S 线只能取 178，与粗糙打法的 175 又只剩 3 分，等于这一轮没改。要「真正拉开」和「最高档代表干净」，这两个目标只能一起满足于 180 + 干净闸。

构建脚本把这条线做成六条硬校验：**漏收一条窗口旁证必须仍 ≥ S 线**、**漏收两条必须 < S 线**、**误收一条冲突/没对上必须 < S 线**；再加上原有的「稳健打法 = 理论最高分」「只认字面 < S 线」「只认字面 / 最优 < 72%」「逢旁证就收 < S 线」。任何一条不成立，`pnpm run demo:sort` 直接失败，不会生成一版"字面也能过关"或"认真读也过不了"的数据。

## 牌序与题库：换内容，不只换排列

- 每种牌序的第一拍固定是完全对上——第一次上甩就命中，不用读说明。
- 中段六拍打乱，**第六拍固定是完全对上**：中段收旁证一定会在后面还留一次命中的时候断连击，不能靠"后面没牌了"赌。
- 最后三拍打乱，且一定不发命中。
- 每局 6 种牌序。点「再来一局」会换到另一种牌序，并有一半概率把两件器物的顺序对调；同一局内不会连续抽到同一种。
- **题库是四个内容不同的牌局**，每局两件器物、六种牌序。开局器物分别是北京保利 / 禹贡Ⅲ、保利香港 / 禹贡Ⅱ、北京保利 / 禹贡Ⅰ、保利香港 / 禹贡Ⅰ，第二件在 11 月 15 日、8 月、秋季之间轮换。页面抽局时排除最近两局，所以连打三局不会撞回同一副牌，也不会反复看到同一个开局。

20 拍里六种状态的分布固定：完全对上 6、口径相容 6、边缘相容 1、冲突候选 2、没对上 3、无从判断 2。缺一种构建就失败。

局与局之间会共用一些写法——冻结语料只有 29 种真实写法（机构 5、时间 17、专场 7），三局 60 张牌不可能逐字不重复。能守住的是「记答案也过不了关」：构建时统计两局之间同一维度、同一写法重合了几张（`shared`），以及其中连判定状态也一样的几张（`sameAnswer`）。当前六对牌局 `shared` 8–16 张、`sameAnswer` 4–8 张；`shared ≥ 20` 或 `sameAnswer > 9` 构建直接失败。

第二轮真正要玩家感到的东西藏在日期精度里：同一个写法「2021年秋季」，对 `2021年12月5日` 这条断言是**边缘相容**（+4），对 `2021年11月15日` 是**口径相容**（+8）。同一个词、不同的断言精度，判据就不同——判定不是看词，是看词和这句话的关系。

## 评级

| 评级 | 分数线（占本牌序最优分） | 说明 |
| --- | --- | --- |
| S | ≥ 180（90%）**且整局没有误收冲突/没对上** | 命中没漏，旁证只在兑现窗口里收，打得干净；漏一条窗口旁证（183）仍在 S 内 |
| A | ≥ 144（72%） | 取舍方向对了一半：要么把兑现窗口里的旁证全放走了，要么在中段收旁证断了连击；分数够 S 但收错过一条，也落在这里 |
| B | ≥ 100（50%） | 只按字面分：命中的都收了，但旁证全放走，兑现窗口一分没拿 |
| C | 0 | 评语按本局实际犯的错生成，落到哪副牌都指名道姓 |

分数线按**这一牌序的理论最高分**折算，不是另定一个绝对目标；结算页同时写出「这一牌序最优 199 分；只认字面相同最多 127 分（64%），见旁证就收 175 分。S 另要求整局没有误收冲突/没对上」，玩家能自己看出差在哪。

结算页的评语不再按档位套模板，而是**数这一局实际犯的错**：放走了几条完全对上、收下几条冲突/没对上、兑现窗口里漏收几条旁证（少拿多少分）、中段收了几条旁证把连击断了、超时几拍——先报数，再给一句下次怎么打。比如只认字面的一局会写「本局收尾窗口里漏收 5 条旁证，少拿 72 分。最后三拍再看一眼器物卡：旁证这时候收才翻倍」；逢旁证就收的一局会写「本局中段收 2 条旁证，把连击断了」。同一句错法不管在哪副牌、落在哪个档，都按本局日志现算，测试可以直接喂一份日志复算。

## 数据从哪来：构建时算好，页面只查表

`pnpm run demo:sort`（`src/demo-page/build-sort-data.ts`）做七件事：

1. 读 `docs/assets/demo-game-data.js`——那份矩阵已由 `build-demo-game.ts` 从冻结底稿 `examples/` 生成，页面链路上不碰原始 JSONL。
2. 按四个牌局计划，各取两件冻结矩阵里真实覆盖的组合（见上节）。
3. 按预先排好的十拍状态序列，从候选池里找写法；同一局两件器物不重复用同一句说法，找不到就直接报错，不擅自放宽候选去凑数。
4. 用 `compareInstitutionDimension` / `compareTimeDimension` / `compareTextDimension` 算出状态与说明，连同器物、状态序列、计分表一起写进 `docs/assets/demo-sort-data.js`（`window.LODESTAR_SORT`）。
5. 每个牌局生成 6 种牌序，并用动态规划求出每种牌序的理论最高分；再用「只认字面」「逢旁证就收」「分段取舍」三种打法各算一遍，另算「分段取舍但在窗口里漏收一条 / 两条」与「误收一条冲突/没对上」三档，校验上面那几条不等式、S 线与干净闸。
6. 校验六种状态一局里都出现、四局开局互不相同；统计两两牌局的重合度并设上限。
7. 全部通过才写文件。任何一条不成立都直接失败，不落盘。

页面脚本 `docs/assets/demo-sort.js` 只做三件事：按牌序发牌、按动作查结算表、把结果与逐条复盘摆出来。**它不重算判定，也不放宽判定**。

「语料外写法」的判据只看冻结语料：把 `docs/assets/demo-data.js` 里出现过的字段值与证据摘到的原值收集起来，不在其中的写法才标出来。这一版标出来的是 `保利拍卖`（同一家，只是少写了城市）、`去年秋天`、`2021年底`、`不详` 一类目录里常见但语料里没有的写法——它们是让「口径相容」「无从判断」两条路在四局里都有不同词可用才放进候选池的。徽章从右上角的「演示用词」改成紧跟在这条值后面的「语料外写法」，首屏说明里也写清：**它只表示冻结语料里没有这个写法，判定仍由引擎把字面值与器物卡比对，不是假数据。**

## 不读字也能玩

页面用四层同时承载同一个判断，任何一层单独都能玩：

1. **颜色**：命中绿、口径蓝、边缘青灰、冲突琥珀、没对上暗红、无从灰；判定行、飘分、粒子都跟着状态走。
2. **进退**：命中时证据卡向上轻推、卡片外缘亮一圈同色光（不盖字）、爆开粒子；掉心时整屏红晕、器物卡红框；连击断在连击条上闪一下。
3. **数字**：分数、倍率、连击数、剩余心、第几件第几拍、十拍进度点、何时进入收尾窗口，随时可见。
4. **一行字**：`这拍 · 状态名 · 后果 · 分数`，就在这张证据卡自己的区域里，卡片同时描一圈同色边——判定和牌是同一个对象，不会看串行。

首屏只有一句「完全对上就收下，连击会翻倍；说法不同（口径/边缘相容）中段先放走，等每件器物最后三拍再收——那三拍多给 0.8 秒；冲突/没对上收下倒扣 6 分，S 档要求整局没有这种误收；长专场名会按行数自动加时」与一个「开始」按钮；完整分值表收在「分值怎么算的」折叠里，点开才看。

## 输入、无障碍与降级

- 指针：证据卡上 `pointerdown` / `pointermove` / `pointerup` + `setPointerCapture`，判定 ±34px；`touch-action:none` 保证纵向甩不被浏览器抢走。触屏与鼠标走同一条路径。
- 键盘：`↑`/`W` 收下、`↓`/`S` 放走、`空格`/`回车` 开始或重开、`P`/`Esc` 暂停或继续、暂停页里 `R` 重来；不需要鼠标就能打完整局。
- 读屏：判定行 `aria-live="polite"`；证据卡 `aria-label` 写「本件时间是…，这条说法是…」；心的容器按剩余数更新 `aria-label`；十拍进度点整体带一句读屏说明。暂停时给游戏外壳与顶栏加 `inert` + `aria-hidden`，暂停页本身是 `role="dialog" aria-modal="true"`，焦点落在「继续」。
- 切页自动暂停：`visibilitychange` 进入隐藏状态时直接进暂停页（不透明遮罩），答题计时与判定停留都冻结；回来必须手动继续，不会在后台被判超时。
- 减少动效：`prefers-reduced-motion: reduce` 下动画压到最短、特效层整层隐藏，判定停留压到 0.9 秒，结算逻辑不变（账先落、表演后放），仍能打完整局。

## 盲测第四轮：节拍跟难度走，S 档要求干净

第四轮盲测只报了两处真问题，这一版也只改这两处，玩法结构没动。

### 一、节拍不再"一刀切 2.6 秒"

上一版每拍 2.6 / 2.3 秒，扣掉卡片显形约 0.3 秒，真正能读的只有 2.3 / 2.0 秒。28 字的长专场名正常读完要 4–5 秒；而收尾三拍（第 8–10 拍）偏偏最费脑——要判「2021年12月 vs 2021年秋季」「2021年12月2日-6日 vs 2021年12月5日」这类相容还是冲突，却和第 2 拍一样只有 2.6 秒。全片最紧的三拍正好是最难的三拍。

现在按难度加时，只加不减：

| 段落 | 上一版 | 这一版 | 可读时间（扣 0.3 秒显形） |
| --- | --- | --- | --- |
| 第一件 · 中段短说法 | 2.6 秒 | **2.6 秒**（不变） | 2.3 秒 |
| 第二件 · 中段短说法 | 2.3 秒 | **2.3 秒**（不变） | 2.0 秒 |
| 第一件 · 收尾三拍 | 2.6 秒 | **3.4 秒**（+0.8） | 3.1 秒 |
| 第二件 · 收尾三拍 | 2.3 秒 | **3.1 秒**（+0.8） | 2.8 秒 |
| 两行以上值 / 超过 14 字 | 2.6 / 2.3 秒 | 基础 + 行数/字数加时（实测 3.8–4.4 秒） | 3.5–4.1 秒 |
| 收尾窗口 + 长专场名 | 2.6 / 2.3 秒 | **4.6–4.9 秒**（实测最长 4.86 秒） | 4.3–4.6 秒 |

加时规则：值折成两行以上时，每多一行 +0.8 秒；总字数（这条值 + 本件同维度字段）超过 14 字时，每多一字 +80ms；两者取较大者，封顶 1.8 秒。判定停留仍是 **1.2 秒**，上一轮刚修好的"判定读得到"没有回收。实测连打四局 80 拍，最长一拍 4.86 秒；这组读数只说明加时确实生效，**还没有真人样本能证明第一次玩的人不再被迫超时**。

### 二、S 档：分数与干净度一起管

盲测"读懂再收"连打四局全是 178、89.5%、S，而粗糙的"逢旁证就收"是 163–164、A——只差 3 分；而且他四局 S 里每局都误收一条冲突、掉一颗心，分数照样 178。最高档只表示"窗口收全了"，不表示"没犯错"。

改法见上文「S 线怎么定的」，三处一起动：S 线抬到 90%（180）、误收冲突/没对上倒扣 6 分、S 档加"整局干净"闸。实测读数（Chromium 自动连打，390×844）：

| 打法 | 得分 / 最优 | 评级 | 评语 |
| --- | --- | --- | --- |
| 分段取舍（读懂再收） | **199 / 199** | **S** | 二十拍全按最优解打，没有可再想的 |
| 同一条打法，误收 1 条冲突 | **172 / 199** | **A** | 收下 1 条冲突/没对上，倒扣 6 分、掉了 1 颗心 |
| 逢旁证就收 | **175 / 199** | **A** | 中段收 2 条旁证，把连击断了 |
| 只认字面 | **127 / 199** | **B** | 收尾窗口里漏收 5 条旁证，少拿 72 分 |

S 线（180）与粗糙打法（175）差 5 分，上一版这条差距只有 2 分；误收一条冲突的 172 既低于线，也被干净闸挡下。所以即使某局分数摸到 180 以上，只要收错过冲突/没对上，最高档仍然拿不到。

## 测试守着什么

`src/demo-page/demo-sort.test.ts`（36 条，离线、零模型调用）守十四件事：

1. **不许放宽判定**：每条说法的 `state` 与 `note` 都用引擎自己的维度函数逐字复算，必须一致。
2. **器物不是编的**：两轮的器物卡必须按 `comboId` 挂到冻结矩阵里 `covered` 的组合，记录号与三个值逐项相等。
3. **六态都碰得到**：每种状态至少一条，不许有一种只写在说明里。
4. **「语料外写法」不多标**：`demoOnly` 必须等于"冻结语料里没有这个写法"。
5. **结算可复算**：倍率分段与上限、各动作的分/连击/心、窗口翻倍、超时，全部与数据表逐项核对。
6. **字面打不到 S**：逐牌序用页面真正在用的结算函数重算三种打法，字面必须低于 S 线且低于最优分的 72%，逢旁证就收必须低于 S 线，稳健打法必须等于动态规划求出的理论最高分。
7. **题库真换内容**：四局开局互不相同、每局六种牌序互不相同；连抽 24 次不会连着两局撞同一副牌，最近两局不会被再次抽到；两两重合度在上限内。
8. **牌序与文案纪律**：每种牌序是完整排列、第一拍命中、收尾三拍不发命中；口径相容必须写「不能算对上」；S 档不许写「每条都判对了」；A/B 档文案必须点明窗口与字面分。
9. **页面不自伤**：脚本里不能用局部变量遮蔽 `window`（上一次改到一半就是这样把 `window.setTimeout` 变成布尔值，游戏卡在第一拍）；判定行必须位于证据卡区块内部。
10. **S 线够得着、也仍有区分度**：逐牌序断言「漏收一条窗口旁证仍 ≥ S 线、漏收两条 < S 线、误收一条冲突/没对上 < S 线」；S 线是 180，盲测的 178 按分数不够；`gradeOf` 在分数够线但整局不干净时不得返回 S。
11. **评语针对本局**：喂一段同时含漏判、误收、窗口漏收、中段收旁证与超时的日志，`diagnoseLog` 的计数与文案逐项对上；全对时写「二十拍全按最优解打」。
12. **六处小修的形制**：判定行固定高度且宽屏不再用 `min-height`、徽章文案与位置、「语料外写法」解释在首屏、复盘默认折叠与切换按钮、开始页滚动提示、判定停留仍是 1.2 秒。
13. **节拍跟着难度走**：中段短文案仍是 2.6 / 2.3 秒；收尾三拍各 +0.8 秒；两行以上值 +0.8 秒、长字数按 80ms/字加时、总加时封顶 1.8 秒。
14. **暂停与重来**：入口按钮与 `P` / `Esc` 键位在页面里；遮罩是整屏不透明（没有半透明层或模糊）、打开时壳与顶栏 `visibility:hidden` 且带 `inert` + `aria-hidden`；tips 是静态 HTML、脚本没有写它的入口；答题与判定停留各有一个冻结点，恢复用冻结的剩余量；倒数期间不调 `resumeClock`；重来必须经二次确认且复用 `startGame`。

测试会把页面脚本装进一个最小的假 DOM 里跑起来，拿到的是页面**真正在用**的那份结算函数（`window.LODESTAR_SORT_RULES`），不是测试另写一套。

## 实测读数

- **稳健打法实打一局**：20 次判决、**199/199、S**，评语「二十拍全按最优解打，没有可再想的」；复盘 20 条全部标「最优」。
- **同一条打法漏收一条窗口旁证**：**183/199、S**，评语直接点名「收尾窗口里漏收 1 条旁证，少拿 16 分」——认真读一局、手滑一次仍拿最高档。
- **同一条打法误收一条冲突**：**172/199、A**，评语「收下 1 条冲突/没对上，倒扣 6 分、掉了 1 颗心」；分数低于 180，干净闸也同时生效。
- **只认字面实打一局**：同样 20 次判决，**127/199、B**，评语「本局收尾窗口里漏收 5 条旁证，少拿 72 分」；复盘默认只展开这 5 条，482px 一屏读完。
- **逢旁证就收实打一局**：**175/199、A**，评语「本局中段收 2 条旁证，把连击断了」，复盘默认 2 行、208px。
- **判定行不顶舞台**：同一拍内判定出现前后，证据卡高度变化 0px，器物卡 y 变化 320 下 0.1px、1440 下 0px（改前是卡片 +36px、舞台 ±19px）。
- **320×568 开始页**：展开规则后面板 10–558 落在 568 高的屏内；988px 内容在 477px 视窗里滚动，底部提示「↕ 上下滑动查看完整规则」常驻，滚到底换成「已到底 · 点「开始」开局」；桌面 1440×900 不溢出时提示自动隐藏。
- **判定归属**：1440×900 与 320×568 下判定行都完整落在证据卡矩形内（实测 `verdictTop ≥ chipTop`、`verdictBottom ≤ chipBottom`），卡与判定一起描同色边。
- **等待反馈**：决定后 320ms 时卡底进度线已走出 167px 且不透明；超时同样立刻出现「超时 · 这一拍没判，连击断」并走进度线，1.4 秒后自动发下一拍。不再有「按了没反应」的空窗。
- **换件提示**：第一件第十拍结算后，标题行下方展开「换下一件 · 连击清零，倍率回到 ×1」，高度从 0 动画到 13.5px，1.9 秒后收起。
- **短甩与点击**：上甩 12px 立刻提示「甩得不够（要 34px 以上）：再甩长一点」，分数不变；点击卡片提示「点卡片不算数」，计时继续。
- **节拍读数（390×844，Chromium 自动连打四局）**：中段短说法 2.6 / 2.3 秒；收尾三拍 3.4 / 3.1 秒；两行以上值实测 3.8–4.4 秒；收尾窗口 + 长专场名实测最长 **4.86 秒**。判定停留仍 1.2 秒。
- **桌面纵向版式（1440×900）**：器物卡 720×172 位于 y≈255，证据卡 660×157，按钮 80 高，页高与视口相等（900 = 900），不滚页。
- **小屏（320×568）**：器物卡 296×90、证据卡 294×112，全部在屏内，`scrollHeight = innerHeight = 568`；屏高不足 640 时十拍进度点按设计隐藏，把高度让给牌与按钮。
- **降级**：`prefers-reduced-motion` 下打完整局仍按同一套结算。
- **暂停冻结（1280×800，Chromium，`file://`）**：收尾窗口的一拍暂停时剩余 **3175ms**，650ms 后仍是 **3175ms**；倒数 3、2、1 期间读数不变；恢复为 `playing` 时 **3173ms**（差 2ms），400ms 后 **2760ms**。判定停留暂停时剩余 **1124ms**，600ms 后不变；恢复后走完余量、拍次 7→8。
- **暂停遮挡**：遮罩 `z-index:30`、整屏渐变不透明；`elementFromPoint` 落在证据卡中心时命中遮罩内元素；壳与顶栏 `aria-hidden="true"`、`inert=true`、`visibility:hidden`，恢复后回到 `visible`；暂停页文字里不含当前牌值、器物卡值、分数与拍次。
- **重来**：`run-1` → `run-2`（`order-4` → `order-2`），分数 13 → 0、拍次回 0，遮罩关闭、`aria-hidden` 与 `inert` 撤销；确认框默认焦点在「先不重来」，`Esc` 收回确认后仍停暂停页。收尾窗口（拍次 7）与判定停留（`pauseKind=wait`、冻结 1104ms）里直接重来也都回到拍次 0、分数 0。
- **窄屏 375×667 与 320×568**：两档下暂停卡片都完整落在视口内、不需要滚动；375 下「继续」「重来一局」在 y≈495–543，320 下压缩字号与间距后在 y≈424–466，底部键位提示也可见。窄屏的暂停按钮是 34px 高，和进度行同高。
- **站点**：`node scripts/check-site.mjs` 覆盖全部 4 个页面并通过；`npx tsc --noEmit` 与 `npx vitest run src/demo-page`（99 条，其中 demo-sort 36 条）通过。

## 还不好的地方

- **中段与窗口的差别要靠算一遍才信**：老手一眼能看出"旁证留到最后"，新手前两局大概率仍会像"只认字面"那样打，掉到 B 档。判定行会写「连击断」「窗口翻倍」，但"+8 换掉后面 20 分"这笔账没有当场算给玩家看。
- **题库只有四局**：页面会排除最近两局，但打到第五局起就会重复；要真正耐玩，得从矩阵里生成更多合格器物，当前候选池只够撑起这几组六态齐备的组合。
- **逐字不重复在数学上做不到**：冻结语料只有 29 种写法，三局要发 60 张牌，机构维每局五张却只有四个可用值。现在守住的是「连答案也一样的重合 ≤ 9 张」，不是「一句都不重」。
- **六态分布不均**：边缘相容整局只有 1 条，且只在 12 月 5 日那件的第一局出现；冲突候选 2 条。教学够用，但玩家一局只碰得到一次边缘相容。
- **桌面留白仍偏大**：1440×900 下三处留白各 110px 左右，内容已经铺满整屏，但信息密度仍低于常见桌面应用；再收紧就要加内容或改双栏，这一轮没做。
- **只有纵向甩**：不像旧页那样支持横向拨卡；本页不需要换页浏览，所以没做。
- **加时是否够用还没有真人验证**：这一轮的节拍读数来自自动连打，只能证明规则生效；第一次玩、逐字读长文案的人是否仍会超时，要下一轮真人盲测才知道。这一版被定为终态，所以若仍不够，只能留到以后处理。
- **窗口内收下冲突的代价现在很硬**：倒扣 6 分、掉心、断连击，再加干净闸，误收一条就基本告别 S。这是有意的取舍——最高档要代表"打得干净"，但对偶尔手滑、其余全对的玩家没有中间档：不会有"分数够线、扣一分变 A+"之类的缓冲。
- **178 分干净局也拿不到 S**：新线是 180。若以后真人样本显示"读对规则、但天生慢一拍"的人稳定停在 178，需要把线降到 178（89%），代价是 S 与粗糙打法（175）又只差 3 分——两个目标此消彼长，这一版选了"拉开 + 干净"。
- **加时按当前渲染行数算，节拍会随视口与字体变**：同一个 28 字专场名在 320 宽折三行、1440 宽折两行，加时长度不同；同一局在手机和桌面上的总时长也就不一样。这是"按实际排版给余量"的必然代价，没做逐设备基准表。
- **长文案的拍会显得"等太久"**：熟练玩家已经扫完前缀，仍要等满 4.9 秒；没有"提前结算 / 跳过等待"的机制。短文案的 2.6 秒对第一次玩的人依然偏紧——节拍现在只是"难题多给、长文多给"，不是"人人够用"。
- **跨拍仍会因长文案轻微跳**：判定行已经定高，但同一局里遇到超长专场名（例如「禹贡Ⅱ—郎世宁绘《纯惠皇贵妃油画像》暨重要宫廷艺术」）时，证据卡本身会多折一两行，器物卡仍会跟着移 13–20px。要彻底不跳，得把每张卡都按最长文案预留高度，代价是每拍都留一大块空白，这一轮没做。
- **全对时复盘仍是 20 行**：默认折叠只对"有错"的局有效；满分一局 20 条全「最优」，仍要滚 1552px。想一眼看完，可把全对也默认折叠，但那样会看不到"逐条核对"的价值。
- **暂停挡得住屏幕与读屏，挡不住开发者工具**：遮罩是不透明 DOM，牌面、分数与剩余时间仍在这张页面的内存里；打开 DevTools、执行 `window.LODESTAR_SORT_RULES.state()` 或改内存仍能读到。前端单页小游戏做不到真正防作弊，这一版保证的是「正常看、正常用读屏」拿不到信息。
- **恢复倒数固定 1.8 秒（减少动效 0.8 秒）且不能跳过**：熟练玩家只想接着打时会嫌慢；没做「按住跳过」，因为那会变成一种可反复利用的暂停节奏。
- **切页自动暂停后必须手动继续**：只是切出去回一条消息，回来也要再点一次「继续」并等倒数；上一版是自动续上。换成手动是为了不让计时在后台跑掉，代价是多一次操作。
- **局中重来要三步**：暂停 → 重来一局 → 确定重来，比结算页的「再来一局」多两层确认。这是防误触的代价，没有做长按或双击直接重来。
- **倒数期间再按 `P` / `Esc` 会退回暂停页，但页面上没写这条**：只写了「按 P 或 Esc 继续」，玩家要自己发现「再按一次可以反悔」。
- **重来本身是一次免费换牌**：觉得这一局不顺手，可以立刻暂停重来，分数归零但没有局数、时间或次数上的成本；`pickRun` 只是保证不会抽回最近两局，挡不住「反复重来直到抽到顺手的牌」。这是「随时可重来」的必然代价，没有加惩罚。
- **暂停按钮只有 34px 高**：比移动端常见的 44px 触控建议小一圈；再高就会把进度行顶起来、挤掉牌面高度。实测 320 宽可点、与进度文字不重叠，但对指头粗的人仍偏小。
- **暂停按钮在进度行右侧，和中间的进度文字离得较远**：宽屏下按钮靠右边缘（1280 下 x≈1017–1072），视觉上像顶栏工具而不是进度行的一部分；功能上没问题，只是不够"长在一起"。
