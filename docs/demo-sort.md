# 证据分拣：上甩收下，下甩放走

一句话：**屏幕下方滑过一条说法，你只有三秒多；能直接当支撑的往上甩收下，其余往下甩放走。**

`docs/demo-sort.html` 是另开的一页。`docs/demo-lab.html`（改词 + 八档图鉴 + 31 分线）原样保留，可以并排对比：那边是"自己拼一句话、看系统怎么判"，这边是"系统把一条条说法递到手上，你替它分拣"。两页读同一份冻结矩阵、调同一套维度函数，判定口径一个字没改。

## 一局的形状

- 两件器物，每件十条说法，共 20 拍；每拍一张证据卡，倒计时 3.2 秒（第二轮 2.8 秒）。
- 一屏之内玩完：上面是这一件的断言卡（机构 / 时间 / 专场三个值），中间是甩的跑道与判定行，下面是证据卡和两个动作按钮。页面定高一屏、`overflow:hidden`，结算表在自己的框里滚动。
- 三颗心。心掉光提前结束，按已打的拍数结算。
- 一局 20 次判决 + 1 次开始。满分局 146 分。

## 核心循环：一次挥动 = 一次判决

| 动作 | 触屏 / 鼠标 | 键盘 | 按钮 |
| --- | --- | --- | --- |
| 收下 | 把证据卡往上甩过 34px | `↑` / `W` | 「收下」 |
| 放走 | 往下甩过 34px | `↓` / `S` | 「放走」 |
| 开始 / 重开 | 点「开始」 | `空格` / `回车` | 「开始」 |

证据卡上直接并排放着要比较的两行：`本件 2021年12月5日` 与 `这条 2021年秋季`。比较发生在拇指边上，不必抬头去卡片上找值。

## 六种状态在玩法里各自是什么后果

判定不在页面里算。每条说法属于哪种状态，是构建时用引擎的维度纯函数算好、冻结进数据的（下一节）。玩法只决定"这个状态 + 这个动作 = 多少分、连击怎么走、掉不掉心"：

| 状态 | 收下 | 放走 | 超时 | 玩家要做的判断 |
| --- | --- | --- | --- | --- |
| 完全对上（按规则归一后一致） | **命中**：10 × 倍率，连击 +1 | 漏判：0 分，连击断 | 0 分，连击断 | 收 |
| 口径相容（说法不同、可能是同一场，但不能算对上） | +3，**连击冻结** | +2，连击 +1 | 0 分，连击断 | 两难：多 1 分，还是保住连击 |
| 边缘相容（没有矛盾，但这不能证明） | +1，连击冻结 | +2，连击 +1 | 0 分，连击断 | 收下基本亏 |
| 冲突候选（点名了另一个值，只作候选、不压成反对） | 0 分，**掉一颗心**，连击断 | +2，连击 +1 | 0 分，连击断 | 不能收 |
| 没对上（证据写的是别的值） | 0 分，**掉一颗心**，连击断 | +2，连击 +1 | 0 分，连击断 | 不能收 |
| 无从判断（解析不出可比的说法） | 0 分，连击冻结 | +1，连击 +1 | 0 分，连击断 | 收下白占一拍 |

这张表就是"相容证据不等于直接支持"的机制化：

- **口径相容只给 +3，而放走它给 +2 且连击继续。** 收下不是错，但只多 1 分就换来连击停住——玩家要靠手感到"它有用，但它不是命中"。
- **边缘相容收下 +1、放走 +2**，收下严格更差。它在说"没有矛盾"并不等于"能证明"。
- **冲突候选与没对上收下直接掉心**，但都还能放走拿 +2；错的是把它当支撑，不是这条说法本身的存在。
- **完全对上放走是漏判**：0 分且连击归零，比任何"放对"都疼。这把"该收的必须收"立住了。
- **无从判断**收下不伤、只冻连击，但白占一拍的时间——它是"什么也没说"的代价。

每拍结束，跑道正中的判定行立刻写一行：`口径相容 · 只算旁证 · +3 · 连击冻结`、`完全对上 · 命中 +20`、`冲突候选 · 掉一颗心 · 连击断`。状态名、后果、分数三个都在同一行里，不需要回看规则表。

## 连击与倍率

倍率只跟连击数有关：`1 + ⌊连击 ÷ 3⌋ × 0.5`，封顶 ×3。

| 连击 | 0–2 | 3–5 | 6–8 | 9–11 | 12+ |
| --- | --- | --- | --- | --- | --- |
| 倍率 | ×1.0 | ×1.5 | ×2.0 | ×2.5 | ×3.0 |

连击条上有三道刻度，正好是三次升档。连击被冻结时整条闪蓝、断开时闪红，变化发生在 100ms 内，不等下一拍。

分数完全可复算：命中就是 10 × 当时倍率；相容证据的分值是固定表；没有随机奖励、没有时间奖励、没有隐藏倍率。一局结束时逐条列出每条说法、它的真实状态、你做了什么、得分或掉心，六种状态各出现几次也一并列出。

## 评级

| 评级 | 分数线 | 说明 |
| --- | --- | --- |
| S | 131 | 每条都判对了 |
| A | 102 | 只放过了几条相容证据 |
| B | 66 | 把相容当成了支撑 |
| C | 0 | 还没分出相容与对上 |

分数线按满分局 146 折算（90% / 70% / 45%），不是另定一套目标，玩家能自己算出来差在哪。

## 数据从哪来：构建时算好，页面只查表

`pnpm run demo:sort`（`src/demo-page/build-sort-data.ts`）做五件事：

1. 读 `docs/assets/demo-game-data.js`——那份矩阵已由 `build-demo-game.ts` 从冻结底稿 `examples/` 生成，页面链路上不碰原始 JSONL。
2. 两件器物固定为矩阵里真实覆盖的两组：第一轮 `g-01`（北京保利 / 2021年12月5日 / 禹贡Ⅰ—盛清御瓷新风尚），第二轮 `g-07`（北京保利 / 2021年11月15日 / 禹贡Ⅱ—郎世宁绘《纯惠皇贵妃油画像》暨重要宫廷艺术）。
3. 按预先排好的十拍状态序列，从候选池里找第一条能算出该状态的写法；找不到就直接报错，不擅自放宽候选去凑数。
4. 用 `compareInstitutionDimension` / `compareTimeDimension` / `compareTextDimension` 算出状态与说明，连同器物、状态序列、计分表一起写进 `docs/assets/demo-sort-data.js`（`window.LODESTAR_SORT`）。
5. 校验六种状态一局里都出现；缺一种直接失败。

页面脚本 `docs/assets/demo-sort.js` 只做三件事：发牌、按动作查结算表、把结果与逐条复盘摆出来。**它不重算判定，也不放宽判定**。

「演示用词」的判据只看冻结语料：把 `docs/assets/demo-data.js` 里出现过的字段值与证据摘到的原值收集起来，不在其中的写法才标「演示」。这一版会标出来的只有 `保利拍卖`（同一家，只是少写了城市）与 `去年秋天`（解析不出可比时间）——这两个值是为了让「口径相容」「无从判断」两条路真实可达才放进候选池的。

## 两轮的教学弧线

状态序列是写死的，不是随机洗牌：

- **第一轮**：完全对上 → 没对上 → 完全对上 → 口径相容 → 冲突候选 → 完全对上 → 边缘相容 → 无从判断 → 口径相容 → 没对上。
- **第二轮**：完全对上 → 口径相容 → 没对上 → 口径相容 → 完全对上 → 冲突候选 → 冲突候选 → 完全对上 → 无从判断 → 没对上。

第一拍一定是「完全对上」——玩家的第一次上甩就命中，不用读任何说明就知道"往上是对的"；第二拍是「没对上」，往下甩也对。两个动作各被确认一次之后，才依次塞进相容、冲突、边缘、无从判断。

第二轮真正要玩家感到的东西藏在日期精度里：同一个写法「2021年秋季」，对 `2021年12月5日` 这条断言是**边缘相容**，对 `2021年11月15日` 是**口径相容**。同一个词、不同的断言精度，判据就不同——判定不是看词，是看词和这句话的关系。

六种状态在这 20 拍里的分布：完全对上 6、口径相容 4、边缘相容 1、冲突候选 3、没对上 4、无从判断 2。

## 不读字也能玩

页面用四层同时承载同一个判断，任何一层单独都能玩：

1. **颜色**：命中绿、口径蓝、边缘青灰、冲突琥珀、没对上暗红、无从灰；判定行、飘分、粒子都跟着状态走。
2. **进退**：收下命中时证据卡向上飞出、爆开光圈与粒子；掉心时整屏红晕、器物卡红框；连击冻结/断在连击条上闪一下。
3. **数字**：分数、倍率、连击数、剩余心，随时可见。
4. **一行字**：状态名 + 后果 + 分数，放在跑道正中。

首屏只有一句「两件器物、二十条说法。能直接当支撑的收下，其余放走。」与一个「开始」按钮；完整分值表收在「分值怎么算的」折叠里，点开才看。

## 输入、无障碍与降级

- 指针：证据卡上 `pointerdown` / `pointermove` / `pointerup` + `setPointerCapture`，判定 ±34px；`touch-action:none` 保证纵向甩不被浏览器抢走。触屏与鼠标走同一条路径，不是只有 hover。
- 键盘：`↑`/`W` 收下、`↓`/`S` 放走、`空格`/`回车` 开始或重开；不需要鼠标就能打完整局。
- 读屏：判定行 `aria-live="polite"`；证据卡 `aria-label` 写「本件时间是…，这条说法是…」；心的容器按剩余数更新 `aria-label`。
- 切页暂停：`visibilitychange` 时停表并保存剩余时间，回来续上，不会因为切标签页被判定超时。
- 减少动效：`prefers-reduced-motion: reduce` 下动画时长压到 0.001ms、特效层整层隐藏，结算逻辑不变（账先落、表演后放），仍能打完整局并拿到满分。

## 测试守着什么

`src/demo-page/demo-sort.test.ts`（18 条，离线、零模型调用）守六件事：

1. **不许放宽判定**：每条说法的 `state` 与 `note` 都用引擎自己的维度函数逐字复算，必须一致。
2. **器物不是编的**：两轮的器物卡必须按 `comboId` 挂到冻结矩阵里 `covered` 的组合，记录号与三个值逐项相等。
3. **六态都碰得到**：每种状态至少一条，不许有一种只写在说明里。
4. **演示用词不多标**：`demoOnly` 必须等于"冻结语料里没有这个写法"，真出现过的写法不许标成编的。
5. **结算可复算**：倍率分段与上限、各动作的分/连击/心、超时、满分局 = `perfectScore`、分数线单调。
6. **文案纪律**：六种状态的标题就是引擎那六个；口径相容必须写「不能算对上」，边缘相容必须写「不能证明」，冲突候选必须写「不压成反对」；收下冲突/没对上的提示里不许出现「命中」。

测试会把页面脚本装进一个最小的假 DOM 里跑起来，拿到的是页面**真正在用**的那份结算函数（`window.LODESTAR_SORT_RULES`），不是测试另写一套。

## 实测读数

- **一屏**：1440×900 / 820×1180 / 390×844 / 360×640 四个视口，`documentElement.scrollHeight` 都等于 `innerHeight`，外壳溢出 0；320×568 下证据卡底边 498 ≤ 按钮顶边 506，不压按钮、不滚页。
- **触屏**：用 CDP 发真实触摸事件上划/下划，判定与按钮一致；第二轮切换正常。
- **响应**：点下按钮到判定行更新约 26ms（远低于 100ms 的门槛）。
- **满分局**：20 次判决、146/146、S、复盘 20 行；脚本按每拍 1.1–1.9 秒的节奏打完 31 秒，游戏内计时同为 31 秒。倒计时合计 60 秒，真人留余量时约 45–60 秒。
- **反面局**：每条都收下，会在第 10 拍掉光三颗心提前结束，37 分、C 级。
- **降级**：`prefers-reduced-motion` 下打完整局仍能拿到 146。
- **站点**：`node scripts/check-site.mjs` 覆盖全部 4 个页面并通过。

## 与 demo-lab 的分工

| | `demo-lab.html`（旧页，保留） | `demo-sort.html`（本页） |
| --- | --- | --- |
| 玩家做什么 | 自己换词、拼一句话，看系统怎么判 | 系统递来一条说法，玩家判断它能不能当支撑 |
| 结局档位 | 八档结论（强 / 弱 / 相容 / 边缘 / 冲突 / 没对上 / 无从 / 没覆盖） | 六种维度状态，一拍一个 |

| 进度 | localStorage 存组合号，刷新不丢 | 不存档，一局打完即止 |
| 判定来源 | 构建时冻结（`demo-game-data.js`） | 构建时冻结（`demo-sort-data.js`），与前者同一套维度函数 |

旧页一个字没改，也仍在导航里。两页读的是同一份冻结矩阵，任一方改了判定口径，另一方的测试会先红。

## 还不好的地方

- **只有两件器物、20 拍**：重玩会记住顺序与答案，不是可以反复刷的 roguelike。要真正耐玩，得从矩阵里生成更多合格器物与不重复的牌序，这一步还没做。
- **状态序列写死**：为了保证教学弧线与"六态必现"，牌序是固定的，不是洗牌。代价是第二局开始就没有"读牌"的新鲜感。
- **只有纵向甩**：不像旧页那样支持横向拨卡；本页不需要换页浏览，所以没做。
- **评级只按满分局折算**：146 是"全判对"的分，不能说明难度曲线是否合理；A 与 B 之间的差距（102 / 66）还没有用真人数据校准过。
