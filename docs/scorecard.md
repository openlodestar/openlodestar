# 评分卡：判定结果比上次好了还是坏了

> 脚本：`scripts/scorecard.ts`
> 考卷：`benchmark/samples.json`（判定批次 + 检索样本清单）、`benchmark/gold.json`（人工金标准）
> 基线：`benchmark/baseline.json`；历史：`benchmark/history.jsonl`

开发做完一轮，最想知道的是一个答案：**判定结果变好了还是变坏了。** 不是"改了多少行"，也不是"测试从 210 条涨到 240 条"——那些是工作量，不是能力。这张卡只量判定结果。

## 一条命令

```bash
# 出分（离线；唯一的写入是往 benchmark/history.jsonl 追加一行）
npx tsx scripts/scorecard.ts
```

| 参数 | 作用 |
| --- | --- |
| `--no-history` | 只出分，不写历史（试跑、排错时用） |
| `--update-baseline` | 把当前读数定为新基线（**只在样本换版时用**） |
| `--commit <标记>` | 给这次读数手动标一个提交号（在提取出来、没有 `.git` 的树里跑时用） |
| `--root <目录>` | 只换样本目录，不换代码；跨提交对照请在各自的检出目录里跑（见文末「怎么比较两个提交」） |

命令本身**不发任何网络请求**：它只读 `examples/` 下的冻结底稿，调 `retallyAndRegate` 离线重算，再读快照核对引文。检索提供者、抓取器、模型客户端都不会被调用。同一个提交、同一份考卷，重跑多少次都是同一组读数（临时目录 + 固定排序，不依赖时间、随机数或网络）。

## 口径（五条硬规矩）

1. **没有总分。** 各分项方向不同——有的越高越好，有的越低越好。硬合成等于先假定"一条误拒等于几次白花检索"，这个换算站不住，所以干脆不算。
2. **分数只来自判定结果。** 用例数、代码覆盖率、测试通过率不进分。用例数只在输出里当附注（`39 条断言 / 82 条证据`）。
3. **未测就写「未测」，不写 0。** 0 分和没测是两件事；混了以后没人敢相信这张表。
4. **样本是固定考卷。** 批次 + 版本号 + SHA-256 锁写进每次输出。换了样本（增删批次、改证据、改期望），锁就变，脚本会明确警告"换考卷后读数不可直接比较"。
5. **每次跑追加一行历史**（提交、日期、样本版本、各项值），累积成表看趋势，而不是只跟上一行比。

**换样本的规矩。** 改批次清单或改批次内容＝换考卷：必须同时升 `benchmark/samples.json` 的对应版本号，然后 `--update-baseline` 重记基线。不许在旧版本号下悄悄改样本刷分——锁会变，输出会红字警告。

### 口径细节

- **一致率是严格一致**：门禁档位（strong / weak / rejected）与坐标有无都必须对上。把 strong 降成 weak 算不一致——这条抓的是"降级"，不重复扣"误拒"。
- **"该拒的有没有拒"**只数金标准里 `gate: rejected` 的记录；要求既拒收、又不产出坐标。
- **"该核的有没有被误拒"**只看"整条被拒收"。档位降级不在这项扣分（那是上一项的事），避免同一个错误扣两遍。
- **可追溯率**逐条证据核对：引文是否逐字出现在它自己的页面快照里（同一套 `quoteMatches`，与 `examples.test.ts` 同口径）。
- **检索条数是预算口径**：用引擎同一套 `buildRecordQueries` 按记录离线复算，取数上限 4 条/记录；不含翻译轨实际加出来的查询，也不是账单上的真实花费。它衡量"同一条断言平均要构造几条查询"，用来发现查询构造悄悄膨胀。
  - 注意：这项**下降不等于进步**。覆盖变窄（比如少查一个字段）也会让条数下降，所以每次都要同时看门禁一致率有没有跟着掉。
- **快照口径**：批次里有 `evidence.enriched.jsonl` 时，评分的临时副本用它覆盖 `evidence.jsonl`（与 `examples.test.ts` 一致）。否则判据三态列读不到，强记录会被误算成弱记录。

### 静态自洽召回率怎么算

这一项回答的是另一类问题：判定判得对，但如果检索根本捞不回能裁的页面，结论也只能是 `not_found`。它不能被离线重算凭空造出来，所以做法是**一次性采样 + 冻结回放**：

1. 采样只用 `llm-web`，每份样本 4 条源查询（引擎的记录级上限），补发最多再加 4 条，合计 8 条；采之前先用干跑模式打印清单，不展开成穷举。
2. 采到的原始结果立刻冻进 `examples/replay-search/<slug>/search-results.json`，并记进 `benchmark/samples.json` 的 `liveRecall` 版本与独立锁。
3. 之后评分卡只读冻结样本，用当前代码重跑路由与候选过滤，**零外部调用**。因此代码改了（路由、过滤、编造判据）读数会跟着变，这正是评分卡要看的。

口径：

- **分母是源查询条数**（引擎决定要问的几个问题）。0 召回补发的译文并入其源查询，不重复计分母；实际检索调用数另记在说明里。
- **分子是"至少一条轨召回到可裁真页"的源查询数。**
- **「可裁」= 静态自洽**：通过候选过滤（含编造链接判据）、通过**域名真实性闸**（域名解析不到的候选淘汰，不进证据链），且标题/摘要含本场关键值。**不抓页、不核逐字引用**——所以它只回答"有没有页可裁"，不回答"页面是否真的支持这条断言"。这条局限没有藏起来。
- **采到多少算多少。** 未配置样本或样本缺失 → 显示「未测」，不显示 0。

当前两份样本的读数（过域名闸后）：`porcelain-2021-autumn` 2/4、`cg-2021-autumn` 2/4，合计 **4/8 = 50.0%**。不过闸时是 5/8 = 62.5%；差的 12.5 个百分点全部来自 `china-guardian.com` / `chinaguardian.com` 这类解析不到的编造域名。逐条查询与成本见 [search-replay.md](search-replay.md)。

**采样本身不是可无限重复的读数。** 一批查询一次采集只是一个快照；想知道"召回稳不稳"，得重复采集同一批查询（语言探针里已经看到同题重跑 2 条 → 0 条）。所以这一项适合看趋势，不适合拿单次差异当定论。

### 可核率、抓页成功率、逐字核验通过率怎么算

这三项把"看着像"升级成"正文里有"，做法同样是**一次性抓页 + 冻结回放**：

1. 抓页只抓**已召回候选页**（检索样本给出的 URL），且**先过域名真实性闸**：解析不到的地址直接淘汰，不浪费一次抓取。不扩查、不新搜、不碰 `serper`；单样本最多 12 页，同域名间隔 2 秒，15 秒超时，不用浏览器渲染。
2. 抓回后在正文里逐字核对机构、专场名、日期：口径与引擎引文核验完全一致（空白与不可见字符不计，字与标点必须一致），**三个字段全部命中**才算这一页可核。
3. 结果冻进 `examples/replay-search/<slug>/page-checks.json`（只存每页的抓取结果与逐字段判定，不存正文），记进 `benchmark/samples.json` 的 `pageChecks` 版本与独立锁；评分卡重跑读它，零外部调用。

口径：

- **可核率的分母是源查询条数**（与静态自洽率同分母，两个数可以直接并排看）；分子是"至少一条候选页抓到且三个字段全中"的源查询数。
- **抓页成功率**：分母是尝试抓的候选页（只含过了域名闸的候选），分子是抓到的页。抓不到单独记一类，**不算召回成功、也不算失败**。冻结样本里因域名闸而离开候选集的历史页记 `orphaned`，不进分母。
- **逐字核验通过率**：分母是抓到的页，分子是关键字段全部逐字命中的页。
- **抓不到页按原因分档**：超时 / 被拦（401·403·429·451）/ 页面结构不符（清洗后正文 < 200 字符）/ 跳转死链（404·410·5xx）/ 不安全地址。混成一个失败率就没有行动价值——死链要从候选里淘汰，被拦要换渲染或通路，超时要重试。**DNS 解析不到的地址已在抓页前按「这个地址不存在」淘汰，不落到这一档**：它与"真实域名但页面下架"是两回事。
- **未抓页的样本显示「未测」，不按 0 算**：某个样本没有 `page-checks.json` 时，它整份不进分母，输出里点名列出。

当前读数（两份样本，抓页样本 24 页、过闸后 13 页）：可核率 **0/8**、抓页成功率 **1/13 = 7.7%**、逐字核验通过率 **0/1**。抓不到的原因：超时 1 · 被拦 6 · 页面结构不符 2 · 跳转死链 3；另有 11 页因域名解析不到被闸在抓页之前（`orphaned`）。逐字段看，抓到的那页里机构、专场名、日期一个都没命中（页面是脚本壳，正文只有 720 字符的页脚）。逐条查询、域名与成本见 [search-replay.md](search-replay.md) 的「抓页可核」一节。

### 正文可读率、两字段、三字段怎么算

这三项回答的是另一个问题：**不是"自己上网能不能抓到证据"，而是"已经落库的页面能不能被裁"**。同样是一次性抽样 + 冻结回放：

1. 从主项目 `shadow_db.pages` 按「正文类型 × 来源域名」分层抽样（层内按 `md5(id)` 排序取前 N，中文页全量），页面正文**只读导出**；
2. 用与引擎同一套清洗器（`processHtml`）拿到正文，再按三档分别判：正文是否 ≥200 字符、机构 + 日期是否核上、再加上专场；
3. 判定读数（含逐字引文片段与字段状态）冻进 `examples/corpus-pages/*.json`，不存全文；记进 `benchmark/samples.json` 的 `corpusPages` 版本与独立锁；
4. 评分卡只读这份判定，零外部调用，重跑同分。

口径（三档分母各不相同，这是重点）：

- **正文可读率**：分母是抽到的全部页。它只回答"材料在不在"，答不了"判据准不准"。
- **两字段可核率**：分母是**可裁决页**（原始正文且可读）。**抽取器模板不进分母**——模板本来就是抽取结果，用它去核抽取结果等于自证；中文媒体稿也不进——它没有"本场"这个概念，记「不适用」。分母之外的数量在输出的说明里逐类点名。
- **三字段可核率**：分母是**场次层契约已满足**的页（`sessionKey` / `sessionName` / `sessionDate` / `houseCanonical` / `language` 五项齐全）。一页都没有时显示「未测」，**不是 0**：0 是"判了但没中"，未测是"这一维没有材料"。
- 判据侧会做两件归一：日期按写法归一后比对（月份缩写、ISO、中文、URL 补年份），机构走 `HOUSE_ALIASES` 的拉丁/汉字别名；**引文始终是页面原文里的逐字片段**。可归一与不可归一的边界、以及会误判的三种情形，写在 [corpus-page-adjudication.md](corpus-page-adjudication.md)。

当前读数（10 页分层样本）：正文可读率 **10/10 = 100.0%**；两字段可核率 **4/4 = 100.0%**（旧口径逐字 2/4；模板 3 页、媒体稿 3 页不进分母）；三字段可核率 **未测**（4 页可裁决页都没有场次记录，缺 `sessionName` / `sessionDate` / `houseCanonical` / `language`）。

**样本只有 10 页，可裁决页只有 4 页。** 100% 是 4 页上的 100%，不是库级的 100%——库级材料结构（218 页里 103 页是抽取器模板，占 47%）写在 [corpus-page-adjudication.md](corpus-page-adjudication.md)。

## 哪些改动不该改变分数

判断改动是否"应该动分"，先问它有没有改变**判定结果**：

- **不该动分**：新增/重命名测试用例、提高覆盖率、调整测试组织；重构（同样输入→同样输出）；改注释、文档、格式化；改日志、追踪、命名。
- **只该动检索条数**：查询构造的等价重写（同样覆盖、更少的查询）、合并重复查询。
- **只该动静态自洽召回率**：检索路由、候选过滤、编造链接判据、域名真实性闸、翻译接线——这些不改变离线判定，但会改变"能捞到多少看着相关的页"。
- **只该动可核率 / 抓页成功率 / 逐字核验通过率**：抓取策略（超时、是否用浏览器）、正文抽取、逐字判据、候选页的域名质量——这三项量的是"抓得到且正文里有"，与搜索排序无关。域名闸会同时动这三项的分母（淘汰的页不再尝试抓取）。
- **应该动分**：改了门禁判据、证据分级、共现规则、引文核对、记录组装——任何会让冻结底稿的结论变化的改动。
- **换样本一定会动锁**：加批次、改证据、改金标准，锁变，读数与旧基线不可比；换检索样本只动检索样本锁。

拿不准时看输出第二、三行：样本锁没变而分数变了，就是代码改动了判定或检索；锁变了，先别比分数。

| 运行 | 门禁一致率 | 该拒的拒了 | 该核的没误拒 | 可追溯 | 检索条数 | 结论 |

读数解读：

- **没变化**：最近三个提交都不改判定，只改路由与样本，分数一条没动。这是正确的——如果这三个提交让分数变了，反而说明有东西在漂。
- **退步**：故障注入只改了一个分支（E1 单一来源的弱坐标被当成拒收），卡立刻点名 `poly-2021-autumn/rec-poly-2021-yugong-2`，并打出两条红标：`⚠ 退步：门禁与人工金标准一致率`、`⚠ 退步：该核的有没有被误拒`。

### 加过滤器导致分数下降：一次真实样本

上线域名闸前后的对照（同一批冻结样本，考卷版本升到 `live-2026-11-09-gate`，所以不能和上表横向比）：

| 运行 | 静态自洽召回率 | 可核率 | 抓页成功率 |
| --- | --- | --- | --- |
| 加闸前 | 62.5%（5/8） | 0/8 | 4.2%（1/24） |
| 加闸后 | **50.0%（4/8）** | 0/8 | **7.7%（1/13）** |

这次下降是设计上预期的：被淘汰的 cg 第 3 条源查询，5 条"可裁"页全部挂在解析不到的 `china-guardian.com` 上。卡把它从"召回成功"改成"未召回"，同时在抓页侧把那 11 页编造地址挡在尝试之前，抓页成功率的分母从 24 降到 13。**遇到这种"加了过滤器、分数反而降"的情况，先看该过滤器是不是在删假阳性**；确认是之后要升样本版本并重记基线，否则退步闸每次都会红。

### 怎么比较两个提交

脚本的模块是按**脚本所在位置**相对导入的，所以 `--root` 只换考卷、不换代码。比较两个提交的正确做法：

```bash
# 1. 把两个提交各自导出成独立目录（git worktree 或 git archive 均可）
git worktree add /tmp/ol-old 5483bf7

# 2. 把评分卡脚本与考卷复制进旧树（脚本本身要跟着旧树，才能跑旧代码）
cp -r scripts/scorecard.ts benchmark /tmp/ol-old/ &&
  cp scripts/scorecard.ts /tmp/ol-old/scripts/scorecard.ts

# 3. 在旧树根目录里跑（cwd 决定加载哪份 src）
cd /tmp/ol-old && npx tsx scripts/scorecard.ts --no-history --commit 5483bf7
```

在错误的目录里跑，会用新代码去算旧样本——分数看起来"没变化"，其实是同一个程序跑了两遍。脚本在检测到 `--root` 指向别处时会打印提示。

## 退步闸

脚本会把任何**比基线更差**的分项打成 `⚠ 退步：<分项>`。阈值目前是 0（一点退步就报），但**只打印，不接 CI、不拦合并**——先跑几轮，看它在真实改动下会不会误报（比如合理的覆盖调整让检索条数可接受地上升），再决定要不要硬拦。真正接 CI 之前，至少要证明：连续多个正常提交下它不红。

## 局限

- **样本小，分辨率粗。** 7 条记录，一条记录就是 14.3 个百分点；分项掉一格往往只差一条记录。它适合看方向，不适合比小数点。
- **在线召回类三项只有两份样本、一个提供者、一次抓页。** 4/8 与 0/8 是 `llm-web` × 两个事件、24 页（过闸后 13 页）的一次快照；同一查询重跑会出现 2 → 0 的抖动，站点当天是否限流也会影响抓页，所以这几项看趋势，不拿单次差异当定论。
- **域名闸只证明"域名解析得到"。** 它拦不住真实域名但页面已下架、改版、被登录墙挡住，也拦不住同形近似的钓鱼域名；DNS 临时抖动按 `unknown` 保留（宁可漏杀不可误杀）。所以 4/8 仍是上限性质的读数，不等于页面里真有这条事实。
- **「可核」只到裸抓 + 逐字。** 不开浏览器渲染：脚本壳页面（抓回 0 字段）只说明这条链路拿不到可核正文，不等于页面上没有这条事实；严格逐字也会漏掉"日期写法不同"这类改写。
- **金标准是人工写死的。** 产品意图变了（例如以后认为某类 weak 记录也该入坐标库），金标准要跟着改并升样本版本，否则卡会用旧标准罚新行为。
- **只覆盖离线判定加冻结检索、冻结抓页。** 真实账单、全站抓取深度、重试成本都不在卡上。
- **检索条数不是账单。** 它是构造出来的查询条数，不含翻译调用、0 召回补发与失败重试的真实花费。
- **快照是节选。** 可追溯率证明"引文在自家节选里逐字出现"，不等于"引文在原始全文里逐字出现"。
