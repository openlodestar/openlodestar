# 检索结果回放（冻结样本）

> 采集 / 重算：`scripts/capture-search-replay.ts`
> 语言探针：`scripts/probe-search-language.ts`
> 回放测试：`src/lodestar/replay-search.test.ts`
> 样本：`examples/replay-search/porcelain-2021-autumn/`、`examples/replay-search/cg-2021-autumn/`
> 探针证据：`examples/replay-search/probe-language/result.json`

前两份落点表（断言路由、预筛）证明的是「判得对」。这一份回答另一个问题：**这些查询到底能不能召回可以裁的页面。** 做法是拿真实记录按引擎的真实检索路径跑一遍，把每条查询的原始结果冻下来；之后所有重跑都读冻结样本，不再联网。

## 这一轮先取证：中文 0 召回不等于「这门语言查不到」

上一轮样本里中文源轨 4 条全部 0 召回，看上去像"提供者对中文查询不给结果"。为免把假象当结论，先用控制变量探针（`scripts/probe-search-language.ts`，只走 `llm-web`）量了一组：中文由宽到窄、英文同宽对照，再刻意只差一个罗马数字「Ⅰ」，最后把同一条窄查询重跑一次。

| # | 语言 | 查询 | 返回条数 |
| --- | --- | --- | --- |
| 1 | 中文 | 北京保利 拍卖 | 0 |
| 2 | 中文 | 北京保利 2021冬季拍卖会 | 0 |
| 3 | 中文 | 北京保利 2021冬季拍卖会 禹贡 盛清御瓷新风尚 | 2 |
| 4 | 英文 | Beijing Poly 2021 Winter Auction | 3 |
| 5 | 中文 | 北京保利 2021冬季拍卖会 禹贡Ⅰ 盛清御瓷新风尚 | 0 |
| 6 | 中文 | 北京保利 2021冬季拍卖会 禹贡Ⅰ 盛清御瓷新风尚 拍卖 专场（冻结样本里的原始查询 #1） | 0 |
| 7 | 中文 | 北京保利 2021冬季拍卖会 禹贡 盛清御瓷新风尚（与 #3 逐字相同，重跑） | 0 |

读数说明（如实）：

- **"中文无效"不成立。** 第 3 条中文窄查询返回了 2 条；同一份证据文件里，重跑它（第 7 条）却是 0 条。**同一条查询两次不同结果**，说明 0 的主因是 `llm-web` 的抖动，不是语言本身。
- **宽的查询确实一直空手。** 第 1、2 条两次都是 0——只给机构名/拍季时，模型联网检索经常直接判"没有相关结果"。这类查询构造本身偏宽，是真实缺陷。
- **罗马数字「Ⅰ」的嫌疑未定。** 第 5、6 条含「Ⅰ」都是 0，但不能归因于「Ⅰ」——同样内容的第 3 条重跑也是 0。抖动掩盖了单变量结论，不硬下判断。

结论：**没有确认"中文查询在这条链路上无效"，因此没有做"中文一律先译再发"。** 那样会把一条有时能召回的中文轨直接扔掉，等于用更贵的确定性换掉一个本来就有时灵的通道。

## 路由改成：源轨先发，只对 0 召回补发译文

判据落在"0 是抖动信号"上：

1. 源查询按自己的语言类先发一次（中文 → `hl=zh-cn`，英文 → `hl=en`）；
2. 翻译与源轨**并行**发起，不拖慢首屏；
3. 源轨里**返回 0 条**的查询，用它的译文再发一次（每条最多补一次，不递归）；
4. 补发不改变分母口径：它并入对应的源查询，不重复计算"问了几件事"。

失败与边界都显式留痕（`RetrievalResult.translation`）：

| 情况 | 行为 | 留痕 |
| --- | --- | --- |
| 翻译成功 | 只补发 0 召回的查询 | `translation.failed = false` |
| 翻译整体失败 | **不补发**，保留源轨结果 | `failed = true` + 原因（"N 条 0 召回查询没有可用译文，未做修复"） |
| 某位译文与原文相同（没翻出来） | 该条不补发 | `untranslated` 计数 + 原因 |
| 源轨已有召回 | 不补发 | 无额外开销 |

成本上界：`检索次数 = 源查询条数 + 补发条数`，补发 ≤ 源查询条数，所以最坏与旧的"无条件双轨"相同；实际只在空手的查询上付第二次钱。

## 编造链接的机械判据

上一轮图录类查询里的 3 条结果自相矛盾：域名是 christies.com / sothebys.com / bonhams.com，标题却是「Poly Auction 2021 Winter Catalog」。这类链接比"质量差"更危险——它会冒充独立第三方，把一条断言推成"多源共现"，等于用假来源把假结论坐实。

判据（`institutionConflictOf`，在候选过滤阶段执行，进证据链之前）：

> **域名注册域属于已知拍行 A，而标题里点名了另一家拍行 B（B ≠ A）→ 拒收。**

- 域名 → 机构：从现状域名白名单的拍卖类条目反查（佳士得、苏富比、邦瀚斯、保利、嘉德、匡时、荣宝、西泠、中贸圣佳等）。
- 标题点名：拉丁别名按整词匹配（`poly` 不会命中 `polychrome`），汉字别名按子串。
- 普通英文词不入判据：`heritage`、`guardian`、`council` 单独出现不算点名（"cultural heritage"不是 Heritage Auctions，"art council"不是北京匡时），只有全称或多词名才算。

**会误杀什么（代价如实写出来）：**

- 拍行官网上转述别家的报道、两家对比文章、行业新闻——标题里必然出现别家名字；
- 联合专场、合作公告、人事变动；
- 标题只是在说"某藏品旧藏于佳士得"这类非事件表述。

**不会误杀什么：** 聚合站与新闻站（雅昌、TheValue、artnet、中国日报等）不在已知拍行域名表里，转述页不受影响。反过来，识别不了的拍行域名（例如不在白名单里的 `polyauction.com`）不会触发——这是**漏杀**，比误杀安全，等域名表扩充时再收紧。

这一轮样本的直接效果：porcelain 样本的候选池从 15 条降到 12 条，剔掉的正是那 3 条自相矛盾链接。

## 域名真实性闸：先判地址存不存在，再谈抓不抓

编造链接判据管的是「域名与标题里的机构对不上」；还有一种更直接的假线索：**域名本身解析不到**。样本里最典型的是 `china-guardian.com`——中国嘉德官网是 `cguardian.com`，前者是模型编出来的地址。旧判据拦不住它（域名不在已知拍行表里），静态自洽也看不出来（只看标题与摘要），一抓页才现原形。

判据（`src/lodestar/domain-gate.ts`，纯机械、零 HTTP）：

| DNS 结果 | 判定 | 处理 |
| --- | --- | --- |
| 解析成功 | `exists` | 保留 |
| `ENOTFOUND` / `NXDOMAIN` / `ENODATA`（明确没有这条记录） | `nonexistent` | **淘汰**，理由写「这个地址不存在（域名无法解析），不进证据链」，不算召回成功 |
| 超时、`SERVFAIL`、`EAI_AGAIN`（这次没问到） | `unknown` | 保留并标注——一次解析抖动不该把真站判死 |

**必须与"真站拒绝抓取"分开。** artnet 403、barrons 401 是真站但挡住了裸抓，归「被拦」，仍留在候选里；把它们和"地址不存在"混成一类，等于把真来源判死。这道闸只回答一个问题：这个域名解析得到吗。

冻结与回放：解析结论写进 `examples/replay-search/<slug>/domains.json`，记进检索样本锁与抓页样本锁；评分卡离线重算读它，零网络。域名不在样本里的候选按 `unknown` 保留，不凭缺失判死。

**本轮淘汰读数**（2026-11-09，两份样本）：

| 样本 | 解析不到的域名 | 被淘汰的候选 URL（去重） | 抓页样本里被拦下的页 |
| --- | --- | --- | --- |
| porcelain-2021-autumn | `polyauction.com`、`polyauction.com.cn` | 4 条 | 4 页 |
| cg-2021-autumn | `china-guardian.com`、`chinaguardian.com` | 13 条 | 7 页 |
| 合计 | 4 个域名 | 17 条 | 11 页 |

候选 URL 比抓页页数多，是因为同一条地址在不同查询的候选集里重复出现。抓页那一栏的 11 页正是本轮原来 14 条「跳转死链」里由 DNS 失败造成的部分；另外 3 条是真实域名但页面返回 404（chinadaily ×2、invaluable ×1），不在这道闸的淘汰范围，仍按死链记。

**加闸后的读数变化（分母不变，仍是 8 条源查询）：**

| 读数 | 加闸前 | 加闸后 | 变化 |
| --- | --- | --- | --- |
| 静态自洽召回率 | 5/8 = 62.5% | **4/8 = 50.0%** | ↓ 12.5 个百分点 |
| 可核率（抓页 + 逐字核上） | 0/8 | **0/8** | 不变 |
| 抓页成功率 | 1/24 = 4.2% | **1/13 = 7.7%** | 分母里 11 页编造地址被拦下，不再白抓 |
| 逐字核验通过率 | 0/1 | 0/1 | 不变 |

被淘汰掉的那一条在 cg 样本的第 3 条源查询：它召回 5 条"可裁"页，全部挂在 `china-guardian.com` / `chinaguardian.com` 上——加闸前算召回成功，加闸后是 0 条，如实记为未召回。**62.5% 里有 12.5 个百分点是编出来的地址撑起来的。**

**这道闸拦不住什么：**

- **真实域名但页面已下架**（404/410）：域名解析成功，闸放行，抓页时才记「跳转死链」。要让这类线索也消失，得靠抓页结果回写候选池，不是 DNS 能做的。
- **真实域名但内容改版、被登录墙或 robots 挡住**：同样放行，归「被拦」或「结构不符」。
- **同形近似的真域名**（例如 `chinaguardian.com` 恰好被注册成钓鱼站）：DNS 只证明"有人解析"，不证明"这就是那家机构"。这需要域名白名单或证书信息，本轮不做。
- **DNS 临时抖动**：判为 `unknown` 保留——宁可漏杀，不可误杀。代价是编造域名偶尔会漏过，等下次解析。
- **DNS 解析成功但指向停放页/广告页**：闸只看域名存不存在，不看内容。

### 在线召回率

- 样本一：2/4（第 1、4 条源查询经补发后各命中 5 / 7 条可裁页）。
- 样本二：3/4（第 1–3 条源查询经补发后各命中 5 条；第 4 条无）。
- 合计（未过域名闸）：**5/8 = 62.5%**，实际发出 16 次检索（每份样本 4 源 + 4 补发）。
- 合计（过域名闸后，当前读数）：样本一 2/4，样本二 2/4 —— **4/8 = 50.0%**。差的那一条是样本二第 3 条查询，它的 5 条"可裁"页全在解析不到的 `china-guardian.com` / `chinaguardian.com` 上。

「可裁」的判据写死在 `src/lodestar/live-recall.ts`：

1. 通过候选过滤（http、非图片/文档、不在黑名单、标题与域名机构不冲突）；
2. 通过域名真实性闸（域名解析不到的候选直接淘汰，不进证据链）；
3. 标题或摘要里出现本场关键值（样本显式列出的跨语言关键词）；
4. **不抓页、不核逐字引用**——这是静态自洽级的代理读数，只回答"有没有页可裁"，不回答"页面是否真的支持这条断言"。

## 抓页可核：把「看着像」升级成「正文里有」

静态自洽只看到搜索结果的标题与摘要。为了回答"页面里到底有没有这条事实"，对同一批冻结查询的**已召回候选页**真抓一遍，用引擎同一条逐字判据核对关键字段。

**判据（写死在 `src/lodestar/page-verification.ts`）**：抓到的页，正文里必须**逐字**出现本场全部关键字段（机构、专场名、日期）；逐字口径与引擎引文核验完全一致——空白与不可见格式字符不计，**字和标点必须一致**。只命中一两个字段不算可核。

**三个读数分开报，不合成一个**：

| 读数 | 分子 | 分母 | 说明 |
| --- | --- | --- | --- |
| 静态自洽率 | 至少一条轨召回到"看着相关"的页的源查询 | 源查询 | 老读数，本轮改名为「静态自洽召回率（未抓页核验）」 |
| 抓页成功率 | 抓到的页 | 尝试抓的候选页 | 抓不到单独记一类，不算召回成功、也不算失败 |
| 逐字核验通过率 | 关键字段全部逐字命中的页 | 抓到的页 | 抓到了但讲的是别的事，记在这里 |
| 可核率（查询级） | 至少一条候选页**抓到且核上**的源查询 | 源查询 | 与静态自洽率同分母，可直接并排看差距 |

**抓不到页按原因分档**（每一档对应不同处理方式，不合成一个失败率）：

| 档 | 判据 | 该怎么处理 |
| --- | --- | --- |
| 超时 | 15 秒内没回话 | 换更长超时／换时段重试，不是"没有这页" |
| 被拦 | HTTP 401/403/429/451 | 要浏览器渲染或换通路，不是"没有这页" |
| 页面结构不符 | 抓回来但清洗后正文 < 200 字符 | 脚本渲染／PDF／空壳页，需要渲染或换材料 |
| 跳转死链 | 404/410、5xx、DNS 解析失败、连接拒绝 | 这页确实拿不到了，要把链接从候选里淘汰 |
| 不安全地址 | 私网、非 http(s) | 不该出现在搜索结果里，属数据质量问题 |

**读数（2026-11-09，抓页样本 24 页；过域名闸后其中 11 页已不在候选集）**：

| 样本 | 抓页（过闸后） | 静态自洽（过闸后） | 可核 | 抓不到的原因 |
| --- | --- | --- | --- | --- |
| porcelain-2021-autumn | 12 页 → 8 页 → 1 页 | 2/4 | 0/4 | 被拦 3 · 死链 2 · 结构不符 2 |
| cg-2021-autumn | 12 页 → 5 页 → 0 页 | 2/4 | 0/4 | 超时 1 · 被拦 3 · 死链 1 |
| 合计 | 24 页 → 13 页 → 1 页（7.7%） | 4/8（50.0%） | 0/8 | 超时 1 · 被拦 6 · 结构不符 2 · 死链 3 |

「12 页 → 8 页」这一步是域名闸：解析不到的地址在抓页前就被淘汰，它们留在冻结抓页样本里的记录按 `orphaned` 处理、不进三个读数的分母。剩下的 3 条死链是真实域名但返回 404（chinadaily ×2、invaluable ×1），与"地址不存在"分开记。

抓到的唯一一页（thevalue.com 的嘉德秋拍文章）正文只有 720 字符、三个字段一个都没出现——页面是脚本渲染的壳，正文不在裸抓的 HTML 里。逐字核验通过率因此是 **0/1**。

**这组读数暴露了什么**：

- **静态自洽率 62.5% 明显高估了这条链路**。样本二那 3 条"可裁"查询里，6 条链接挂在 `china-guardian.com` 上——**这个域名根本不存在**（中国嘉德的官网是 `cguardian.com`）。它们是模型编出来的地址，域名不在已知拍行表里，所以旧的编造判据拦不住；静态自洽只看标题与摘要，自然看不出来，一抓页就现原形。域名闸上线后这两条样本的静态自洽读数降到 **4/8 = 50.0%**，与"有哪些页真的能抓"更接近，但仍不等于可核率。
- 样本一的候选里同样有 `polyauction.com` / `polyauction.com.cn`（无法解析）这类编造域名。
- artnet、barrons 是**真的存在但不让裸抓**（403/401），与编造的死链必须分开处理：前者要渲染或换通路，后者要从候选里淘汰。
- 裸抓拿到 0 字符的 artron、liveauctioneers 属脚本壳，需要浏览器渲染才可能核上；本轮按边界不开浏览器，如实记成"结构不符"。

**会误杀 / 会漏判什么**：

- **严格逐字**：页面把日期写成「2021年11月26日-12月13日」而断言是「至」，判不命中。这是有意的（与引擎引文判据同一条），代价是日期维最容易掉。
- **只抓每样本前 12 页**：候选多于 12 条时后面的页没测，读数只代表抓到的这批；已不在当前候选集里的旧抓页结果记 `orphaned`、不进分母。
- **单次快照**：站点当天是否限流、是否换版都会影响结果；本读数不是稳定属性，换时段抓可能不同。
- **裸抓不等于"页面没有这条事实"**：抓到 0 字段的脚本壳页，只说明这条链路拿不到可核正文，可能要上浏览器渲染才算数。

**采集命令**（默认不联网）：

npx tsx scripts/capture-page-checks.ts --sample porcelain-2021-autumn

抓页样本写在 `examples/replay-search/<slug>/page-checks.json`，只存每页的抓取结果与逐字段判定（**不存正文**）。评分卡重跑读这份样本，零外部调用。

npx tsx scripts/capture-domain-checks.ts --sample porcelain-2021-autumn

## 回放怎么跑

```bash
# 采集（会花钱；默认不带 --allow-spend 只打印查询清单）
npx tsx --env-file=.env scripts/capture-search-replay.ts --sample cg-2021-autumn --allow-spend

# 只改读数口径（过滤规则、关键词）时离线重算，不发请求
npx tsx scripts/capture-search-replay.ts --sample cg-2021-autumn --recompute

# 回放：读冻结样本，用假提供者 + 冻结译文重跑，零网络
npx vitest run src/lodestar/replay-search.test.ts

# 抓页读数：离线重算（读冻结的 page-checks.json，零请求）
npx tsx scripts/scorecard.ts
```

回放测试断言五件事，任何一处漂移都会红：

1. 查询构造结果与冻结时逐条一致（样本换版先在这里暴露）；
2. 检索次数一致（预算记账没被改过）；
3. 每条查询的返回条数一致（同一条查询拿回同一批结果）；
4. 候选过滤后的条数一致（黑名单、去重、排序、编造判据没被动过）；
5. 0 召回补发的条数与译文一致（路由没被悄悄改回双轨或改成不补发）。

样本自带 `version` 与 `capturedAt`；采集用的模型名（`LLM_WEB_MODEL`）与上限（`maxSearchCalls` / `numResultsPerQuery`）也写进样本，换模型或改上限时读数不可直接比较。当前两份样本都是 `version: 2`（对应"源轨 + 0 召回补发"的路由）。

## 这次样本的局限

- **只有两条记录、一个提供者、一个模型。** 4/8 是这两个事件 × `llm-web` × 一个模型名下的读数，不能推及全部记录。
- **0 召回是抖动，不是稳定属性。** 单次采集只能给一个快照；要估计稳定性得重复采集同一批查询（本轮只在探针里重跑了一次）。
- **抓页只覆盖了每样本前 12 页，且只抓了一次。** 过闸后 13 页里 12 页没拿到，结论是"这条链路现在拿不到可核材料"，不是"这些事件在互联网上不存在"。重抓、上浏览器渲染、换通路都可能改变读数。
- **样本二的图录查询没有可裁页。** 通用图录页能否作为证据，取决于后续判据是否接受"机构 + 拍季"级别的页面；本轮按严格口径不计。
