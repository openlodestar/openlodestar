# 场次层证据：46 条真事件的实测，与「场次页落库」和「多页证据」两条路

> **一句话结论**：这批真材料先纠正了一个前提——**单件页并非一律不写专场名**（Christie's 中文站的面包屑就逐字写着），但**机构名在这些页上通常只存在于域名、logo 与邮箱里**，正文唯一一次 `Christie's` 出现在推广卡片上。所以"三字段在单件页上不成立"仍然成立，病因不是"没有专场名"，而是"机构没有被正文证实"。在场次页落库之前，**严格口径的三字段可核是 0/46**；把适配器模板当正文会得到 46/46，那是自证，不能用。
>
> 第六、七、八节把决策闸与渲染复核跑完了：Bonhams 7 个场次页三样字段全是明文，覆盖 **29/46 条事件（63.0%）**；Christie's 3 个场次页只有场次名是明文，机构与日期要客户端渲染，17 条全部记一字段。分母已补满：**三字段 29 条、一字段 17 条、判不了 0、未测 0**。只用一次真实渲染复核过最可能救回的那一页：日期救回了，机构仍然判不了，所以渲染不改变三字段的 63.0%。**路 A 成立，做法是场次页核一次、整场共用，但按站点分批铺。** 机构在可见明文里拿不到的场次（佳士得三场），机构**一律降为域名断言**：记一条，但不进逐字证据、不进三字段分母——这条口径写死在第九节。
>
> 本文只回答读数与设计问题，不实现任何采集或判据改动。所有数字可用 `npx tsx scripts/score-session-pages.ts --dump <只读导出>` 复算。

## 四、两条路怎么改判据、各要付什么代价

### 路 A：采场次页落库，让专场名有真实出处

**判据改法**：三字段的裁定对象从单件页换成**场次页**。一条价格事件先挂到场次（现有的 `saleUrl` 关联），再对场次页做一次"机构 + 专场名 + 举办日期"的逐字核对；三项都在这一页上，`SessionLayerRecord` 的五个字段不再需要从单件页硬凑。单件页只负责器物与价格，不再承担三字段。

**代价**：
- 要采 10 个场次页并落原文（现在 0 页）；65 个场次里 3 个没有 canonical URL，采不到。
- 场次页要过和单件页一样的拦截/脚本壳/截断问题；Bonhams 场次页能不能拿到正文，当前没有样本可证。
- 事件→场次的链接要能从场次页正文里得到旁证，否则仍然只是数据库 join。已经出现一个反例：原文页面包屑写的是 `Live Auction 21663`，而我们的 `sales.external_sale_id` 是 `29896`——两个编号体系并不自动对齐，不能拿页面上的编号当关联键。

**在现有数据量下能撑起多少**：
- 上限 **46/46 事件、10/10 场次**（10 个场次都有 URL，46 条事件全部落在这些场次里）。
- 但这个上限取决于场次页正文是否含"拍行名 + 场次名 + 日期"三样明文。按站点拆：Christie's 3 个场次（17 条事件）较有希望；Bonhams 7 个场次（29 条事件）未知。
- 实测下限是 **0**，直到场次页真的落库并通过逐字核对。不能把"应该能"写成读数。

### 路 B：多页证据，机构与日期来自单件页、专场名来自场次页

**判据改法**：一条证据从"一个页面 + 一段引文"变成"一条事件 + 每个字段各自的来源页与引文"。三字段成立的条件变成：机构、日期在单件页上逐字命中；专场名在场次页上逐字命中；且两页之间的关联有旁证（不是只靠数据库 join）。"同一页逐字"被替换成"每个字段在自己的来源页上逐字"。

**代价**：
- 每条事件要挂两个来源，证据结构、存储、重验都要改；截断、重抓、页面改版会让两个来源不同步。
- 关联本身无法自证：如果单件页上没有任何指向场次页的明文（这次唯一一页原文的面包屑只写了场次名与编号，且编号与我们的场次键不同），那么"这条拍品属于那场"仍然只是我们说的，不是页面证的。
- 当前数据量下，路 B **不比路 A 多核出任何一条**：44 张单件页没有原文，唯一一张原文页的机构命中还是推广卡片；而专场名无论如何都要场次页。也就是说 B 多付一层的代价，换来的是 0 条增量。

**在现有数据量下能撑起多少**：不落场次页时 **0/46**；落了场次页后与路 A 同分母。只有出现"场次页没有机构明文、而某些单件页有"的站点时，B 才有增量——当前 46 页里没有这种页面。

## 五、倾向与失效条件

**倾向：默认走路 A，路 B 只作为机构字段的定点补位，不要在全局把三字段拆成两页。**

理由三条：
1. 一个来源、一条证据、逐字规则不变，最符合现有 `SessionLayerRecord` 契约，也最容易向店主解释"这页上写着"。
2. 这批真材料暴露的缺口是**机构没有被正文证实**，而机构恰恰最可能出现在场次页的页头/页脚；路 B 从单件页拿机构，在当前页面上拿不到。
3. 路 B 的增量依赖"单件页有机构明文 + 场次页没有"，这次 46 页里一个这样的样本都没有；在没有样本支持前先加一层复杂度，是拿确定的成本换不确定的收益。

**决策闸（已于 2026-11-09 执行，读数与结论见第六节）**：抽 3 个场次页——Bonhams 两个（32090、32202，覆盖 19 条事件）、Christie's 一个（29896，覆盖 9 条事件）——只看正文是否同时含"拍行名、场次名、日期"三样明文。
- 三页都含 → 路 A 可以直接把 10 个场次页纳入，上限 46/46，先按实测读数报，不预支。
- 只有 Christie's 含 → 路 A 能撑 17/46、3/10；Bonhams 仍是未测，不要用域名冒充。
- 三页都不含 → 三字段在当前数据下无法成立，应停止报"三字段可核"，改报"两字段 + 场次名仅在场次页可核"两档，并把机构降为结构化断言（域名），明确标注不是逐字证据。

**路 A 的失效条件**：
- 场次页被拦、是脚本壳、或只给一个场次编号而不写场次名。
- 机构只以 logo/图片出现，正文没有拍行名。
- 场次页的日期写的是预展日期而不是举办日期。
- 事件→场次链接错误（`21663` 与 `29896` 这种编号错位就是现成反例）。
- 跨站场次（`.com.cn` 单件页挂 `.com` 场次记录）在语言或场次名写法上不一致。

**路 B 的失效条件**：
- 两页之间只有数据库 join，没有页面上的互相指认，三字段会"验证"一个错误的关联。
- 两个来源在不同时间抓取，描述的可能不是同一场次。
- 每个字段的引文各自成立，但拼起来不成立（例如机构来自同站另一场次的页脚）。

### 机构的口径：拿不到明文就降为域名断言，不进三字段

佳士得的机构名在可见明文里拿不到——它只在图形标识里。这类情况**降为一条域名断言**：落点主域名与机构在别名表里对得上（`christies.com.cn` ↔ `Christie's`），记 `证据种类 = domain`、`verbatim = false`、`quote = null`。它是**一条记录，不是一条证据**：

1. **不进逐字证据**：原来判不了的机构仍是 `unjudgeable`，域名对得上也不能改写成命中；
2. **不进三字段分母**：只有机构、专场名、举办日期三样都在同一张场次页上以可见明文出现，才算一条三字段；机构只能出域名断言的场次，按场次层契约记「两字段」或「未测」；
3. **渲染、JSON-LD / meta、域名断言三者互不折算**，任何一项都不许补进三字段的分子。

判定标准只有一句：**分子里的每一条，都必须能指向同一张场次页上的一段可见明文引文。**

### 写死的现状上限

**这批 46 条真事件的三字段可核上限是 29 条 = 63.0%，另外 17 条结构性卡死。** 29 条全部来自 Bonhams 的 7 个场次；17 条是佳士得的 3 个场次，机构名只以图形标识出现。这个数不会因为换判据口径往上走——只有站点本身改版（机构名以可读文本进入页头/面包屑/标题区/场次抬头）才会。**不许为了凑数把渲染、JSON-LD/meta 或域名断言混进三字段。**

## 十、能对外说的一句结论

**在这批 46 条真实事件上，三字段可核 29 条（63.0%），全部来自 Bonhams 的 7 个场次；佳士得 17 条按可见明文口径暂不计入。**

做法不是"每个事件都落到场次页"，而是**场次页核一次、整场共用**：10 个场次页覆盖 46 条事件，抓取量是逐条核的 1/4.6。便宜的代价是把"事件属于这场"这件事从页面证据里挪到了**关联键**上——页面只证明"这一场是哪家、叫什么、哪天办"，不证明"这件货属于这一场"。

下面把这个模式的两面都写死：先写它凭什么成立、怎么自检（不是只写什么时候会坏），再写快照怎么留、什么时候重核，最后给一份加新站时的操作清单。

### 10.1 成立前提：一条事件要能被称为"属于某场"

五条**同时**满足才算成立，缺任何一条就降档（写成"未测"或"判不了"），不能靠推断补齐：

| # | 前提 | 为什么必须有 | 这批数据里的实况 |
| --- | --- | --- | --- |
| 1 | **归属键唯一且精确**：事件带 `provenance.saleUrl`，规范化（去尾斜杠、去查询串、统一大小写）后与场次表 `canonical_url` 完全相等 | 整场共用只核一次，核错了就是整场一起错；用"包含 / 前缀 / 相似"匹配会把相邻场次混进来 | 46/46 都靠这条键挂上；但键本身不来自页面，见 10.2 的旁证要求 |
| 2 | **场次主键唯一到"一年一场"**：带年份或站点场次编号，不能只有场次名 | 每年都有 `Asian Art`、`Fine Chinese Art`，只用名字会把今年的事件挂到去年的场次页 | 10 个场次都带 `sale_date`（精度全是"日"）与站点编号 |
| 3 | **场次页本身可读**：HTTP 200、不是拦截页、不是脚本壳、不是截断 | 脚本壳里读不到明文的字段，只能记"未测"，不能因为"页面上应该有"就记命中 | Bonhams 7 页全部满足；Christie's 3 页是脚本壳，所以只核到场次名 |
| 4 | **该字段在页面结构位置上逐字成立**：机构看页头/面包屑/标题区/场次抬头，场次名看标题区，日期按写法归一 | 这是"逐字证据"的定义；正文顺带提及、推广位、邮箱、页脚都不算 | 见第七、九节的逐页读数 |
| 5 | **事件日期落在场次日期窗口内**：同日，或场次本身跨多日时落在其起止区间内 | 归属键写错时，日期通常是第一个露馅的地方；窗口外必须人工复核 | 这批 46 条与 10 个场次日期全部同日，没有一条越窗 |

第 5 条是这批数据里**唯一一条来自事件自身、可以反向校验归属键的证据**。前四条都在证明"这一场是什么"，只有它牵涉"这件货是不是这场"。

### 10.2 自检：怎么机械地确认这五条

自检不是再读一遍页面，而是五个能跑出通过/不通过的断言：

| 检查 | 怎么跑 | 不通过怎么处置 |
| --- | --- | --- |
| 键精确 | 每场次统计 `count(distinct normalized(saleUrl))`，必须等于 1；再反查该 URL 在 `sales.canonical_url` 里的命中数，必须等于 1 | 命中 0 → 该批事件记"未测"；命中 >1 → 场次表有重复行，先合并再核 |
| 主键带年份 | 场次的 `sale_date` 非空、精度到日；同一 `(house, sale_name)` 在 ±1 年内不得出现两次 | 出现重名跨年 → 主键补编号，重核该场 |
| 页面可读 | 落库时记 HTTP 状态、正文可读字符数；正文 < 3,000 字符或可读区里出现 `<chr-…>` 这类空自定义元素 → 标"脚本壳" | 标脚本壳的场次，三字段一律记"未测"，不许按 JSON-LD 补 |
| 字段逐字 | 跑 `extractHouseRegions` 看四个结构区域是否抽得出；抽不出 → 该站结构映射缺失，记"判不了" | 记"判不了"而不是"没写"；补结构映射后再核，不要退回整页扫描 |
| 窗口校验 | `abs(事件日期 - 场次日期)` = 0，或落在场次起止区间内 | 越窗 → 该事件单独标"待复核"，不自动挂场次页结论 |
| 整场共用的旁证 | 从场次页的拍品列表里抽 1–2 件，与事件页的 lot 号或器物名对上 | 对不上 → 该场次的归属键可疑，整场降为"未测" |

最后一条是把"整场共用"从**假设**变成**抽检过的假设**：它不用逐条抓，但必须每场至少抽一次。这批 10 个场次里，Bonhams 32090 / 32202 两页的拍品列表能与事件页对上（lot 号与器物名均在），可以作为该站结构可信的旁证；Christie's 三页的拍品列表是空自定义元素，抽不了，所以它们的归属只靠键，不靠页面。

### 10.3 落库：留快照与抓取时间

**要留，而且事件只能引用快照，不能每次重算。** 最小形态：

| 存什么 | 为什么 |
| --- | --- |
| 场次页 URL + 抓取时间（到秒）+ HTTP 状态 + 最终落点 URL | 页面会重定向（佳士得 `.com → .com.cn`），落点与请求地址必须都留，否则复现不了 |
| 正文可读文本（或可回链的正文哈希 + 取文本方式） | 逐字引文必须能回到当时那一版；只存 URL，页面改版后引文就成了"查无此文" |
| 内容哈希 | 判断"页面有没有变"，比逐字 diff 便宜，也是重核的触发开关 |
| 三字段判定结果 + 判据版本号 | 判据改过（本轮就改过机构口径），旧判定必须能说清是按哪一版算的 |
| 每字段的引文与位置 | 举证用；`位置` 记 `header / breadcrumb / title / sale-heading` |

事件表那一侧只存 `snapshotId`，不再重复存三字段：核一次、整场共用，引用同一个快照。这样"哪条事件用了哪一版页面"是可查的，也不会出现同一场次里两条事件挂着两版不一致的结论。

### 10.4 快照过期后什么时候重核

五类触发，任一命中就重核该场次并写新快照（旧快照保留，不覆盖）：

1. **内容哈希变了**：重抓同一 URL 得到不同哈希——场次页在开拍前后改动最频繁（加场次结果、改日期、撤拍品）；
2. **时间到期**：距场次日期 14 天内的页面每 7 天重核一次（临开拍变动多）；开拍后满 90 天转"归档态"，只在其他触发命中时才碰；
3. **判据版本升级**：判据代码变了（如本轮机构口径）——这类只需重判已存快照，**不必重抓**；
4. **场次主数据被改过**：库里 `sale_name` / `sale_date` / `house` 任一更新，说明断言变了，判定必须重跑；
5. **页面撤档或改版**：重抓得 404 / 410 / 跳转到首页——标"页面已撤"，旧快照仍可引用但必须标注"证据为历史快照"，并把该场次从"可核"降为"历史可核"。

另有一条**不该触发重核**的：页面只是排版变了、三字段明文没变（哈希变但字段抽取结果不变）——记一次"页面变动、结论未变"，不升级证据版本。

### 10.5 下次有人加新站时照这个做

1. **先探一页，不要先铺量**：从该站挑一个已入库的场次页抓一次，记 HTTP 状态、正文可读字符数、三样字段是否在结构位置里逐字出现。
2. **判定形态**：正文 < 3,000 字符、抬头是空自定义元素 → 直接记"脚本壳，不做明文核"，要么单开"结构化数据断言"一档，要么先按第八节那一页的实测判断渲染值不值（那里花了 30.5 秒只救回日期，机构仍判不了）；两者都不属于逐字证据，不要混算。
3. **补结构映射**：跑一遍结构区域抽取，页头/面包屑/标题区/场次抬头有一个抽不出来，就先按站点补选择器，再谈判据；不要因为抽不出就退回整页扫描。
4. **做一次归属抽检**：从场次页拍品列表抽 1–2 件，与事件页的 lot 号或器物名对上，确认"整场共用"在这站成立。
5. **落快照再报数**：URL、抓取时间、HTTP 状态、落点、正文、哈希、判据版本一起入库，然后才把读数填进本文的分档表；不达标就写进 10.6 的失效条件，不要为了凑分母硬算。

### 10.6 失效条件（这个模式什么时候不成立）

1. **关联键断了**：事件没带 `saleUrl`、URL 换域名（佳士得 `.com → .com.cn`）、场次 URL 改版或重定向，都会整场错挂或整场判不了；
2. **机构是子品牌**：31803 的页面抬头写 `Bonhams Cornette de Saint Cyr`，库里 `house` 是 `bonhams`；判据若要求全称逐字，这类会被判不中，别名表必须覆盖子品牌；
3. **同名场次跨年**：每年都有 `Asian Art`，场次主键不能靠名字，必须带年份或场次编号；
4. **标题分段**：如 32697、32511，库里用冒号拼、页面分两块，整串严格比会误报"没写"；
5. **页面被撤/归档**：场次页 404 后整场证据失效，落库时必须留快照，不能只存 URL；
6. **货不来自这场**：私洽、线上专场、跨场合并的货若被挂到场次页，会张冠李戴——这一类必须逐条有出处，不能共用。

## 十一、边界与复现

- 只读主项目库：一条 SQL 查场次表（10 个场次的 URL/名称/日期/拍行），不写库、不改采集代码、不碰母仓。
- 第四、五节：不联网、不抓页、不碰 serper、不调 LLM，外部调用 **0**。
- 第六节（三页决策闸）：抓 3 个场次页，HTTP 请求 **3 次、失败 0 次**。
- 第七节（余下 5 个 Bonhams + 2 个 Christie's 补抓）：HTTP 请求 **7 次、失败 0 次**；同域间隔 ≥2.1 秒，未重试。
